# STM32F407 FreeRTOS 启动骨架

这是独立的交叉编译目标，暂以 STM32F407VG（1 MiB Flash、128 KiB 主 SRAM）为参考芯片；参考外设引脚见下文，检测配方和实际板级配置尚未确定。时钟采用复位后的 16 MHz HSI，CMSIS 启动代码初始化 FPU，FreeRTOS 使用 Cortex-M4F 硬浮点端口。默认固件只创建每秒递增 `tp_scheduler_heartbeat` 的任务，调试器可观察该变量；另提供可选业务入口。断言会关中断，强制参考阀门、泵使能和加热输出进入关闭状态后停机；复位阶段、CPU 卡死以及独立硬件保护仍需另行处理。

需要 CMake、Ninja 和 arm-none-eabi-gcc（本机使用 GCC 16.1.0）。在本目录执行：

```powershell
cmake -S . -B build -G Ninja "-DCMAKE_TOOLCHAIN_FILE=$PWD/arm-gcc.cmake"
cmake --build build
```

输出 `tp_f407.elf`、`tp_f407.hex` 和 `tp_f407.map`。链接使用 nosys，未提供标准 I/O 系统调用，工具链可能对此发出警告。链接时保留板级装配入口及其依赖，检查完整链路能否链接；当前心跳主程序并不调用该入口。必须核对实物型号、Flash 大小、引脚、电气安全态和保护电路后才能实现板级对接；此链接布局尚未划分 Bootloader 或 OTA 区域。实机尚未验证。

依赖来源：FreeRTOS Kernel V10.5.1（随源码 MIT 许可）；CMSIS 5.9.0 Core（Apache-2.0）；ST CMSIS Device F4 v2.6.10 与 STM32F4 HAL/LL 头文件 v1.8.5（许可证各随目录保存）。项目目前只引入 LL 头文件，尚无具体 LL 外设驱动实现。

## 参考存储总线

`tp_f407_i2c.c` 提供 I2C2 到 `tp_i2c_io` 的适配，假设单主机、PB10=SCL、PB11=SDA（AF4）、外部上拉、APB1 16 MHz、100 kHz，目标器件为 MB85RC16。此引脚没有出现在旧设备树的阀门或 USART3 分配中，仍须按实际原理图核对。初始化前调用 `SystemCoreClockUpdate()`；驱动只接受 HSI 16 MHz 且 AHB/APB1 不分频的配置。I2C 操作限时，错误后重置外设；物理总线卡死需要硬件恢复，驱动不会自动输出九个恢复脉冲。事务在调度器启动前单线程执行，调度后使用互斥锁；只在低优先级存储任务调用。

连接顺序：`tp_f407_i2c_init` → `tp_f407_i2c_io` → `tp_mb85rc16_init`（存储区起始 256 字节对齐）→ `tp_mb85rc16_store` → `tp_runtime_bootstrap_storage`。各对象及其上下文须长期有效。当前心跳主程序不调用这条链路；I2C 时序、上拉、电气参数、总线错误恢复和掉电保存都尚未在目标板验证。

## ADS1220 SPI2 参考接口

`tp_f407_ads1220_spi` 假定系统和 APB1 均为 16 MHz，使用 SPI2 模式 1、1 MHz，PB13 SCK、PB14 MISO、PB15 MOSI、PB12 软件片选，PE14 上拉输入作为低有效 DRDY。初始化必须在调度器启动前执行一次，设备实例持续有效；接口不可从中断调用。传输竞争时立即返回忙，单次事务上限 5 字节，循环等待设有 1 ms 周期计数期限（不限制抢占时间），错误时释放片选并重置 SPI。该设备需与 SPI2 的其他使用者共享同一互斥策略。

本接口和通用 ADS1220 驱动已列入交叉编译，但尚未由心跳主程序初始化，链接垃圾回收可能移除它们；引脚电气连接、时序和模拟采样均未在硬件上验证。

## USART3 / RS485 参考端口

`tp_f407_usart3_rtu` 使用 PD8 TX、PD9 RX、PD10 高电平使能 RS485 发送，收发器 DE 与 /RE 相连；TIM5 提供可供通信端口共享的 1 MHz 微秒计时，须在调度器启动前初始化且运行时不得重置。系统时钟和 APB1 为 16 MHz，通信参数固定为 115200 8N1。任务接收中断事件并调用 RTU 分帧器，控制任务通过发送接口复制响应；队列溢出会丢弃当前帧，发送完成中断释放方向。业务装配已连接此端口，默认板级配置仍需由用户提供。时间戳含中断延迟且排队/抢占行为未经目标板测试；确认收发器及接线后用逻辑分析仪验证时序。

## UART4 从控参考端口

`tp_f407_uart4_subordinate` 提供可选主控通信任务，参考 PC10 TX、PC11 RX、AF8、115200 8N1 和全双工 TTL 电平；引脚复用、共地、电平及实际连接必须按芯片型号和原理图核对。该接口不控制 RS485 收发方向。TIM5 与 USART3 共用，时钟假设为 HSI/APB1 16 MHz。UART 中断将事件送入 128 项队列，任务独占协议状态；队列溢出或 UART 错误使状态失效。发送非阻塞并复制请求，遇到在途发送或未处理输入返回忙。任务优先级、栈大小及轮询、超时和有效期由板级配置指定。

可选调用 `tp_f407_uart4_subordinate_set_wakeup` 配置高电平唤醒输出回调和等待毫秒数：请求先置高唤醒线，等待至少所设时间后才开始发送，收到应答或超时后、发送结束时置低。等待计入请求超时；请给等待、发送和应答预留足够时间。回调须立即驱动 GPIO、简短且非阻塞，高电平设置在临界区执行。等待期间收到串口数据会使请求失败；等待结束时如输入队列或 UART 有待处理数据也会中止请求。默认没有唤醒线，F030 可选 STOP 已接入，GPIO 实物接线仍需完成；F030 可选使用 PA8 接收唤醒信号；不能单凭该选项宣称低功耗通信完成。此功能尚未实机验证。

参考接线可在初始化 UART4 后调用 `tp_f407_uart4_subordinate_use_pc8_wakeup(&uart, delay_ms)`：F407 PC8 为高电平有效的推挽输出，连接 F030 PA8 并共地；F030 构建时启用 `TP_F030_WAKE_INPUT`。函数先预置低电平再切为输出。复位期间 PC8 为输入，F030 PA8 的下拉使信号默认为低；请按实际板卡核对电压、引脚占用和唤醒等待时间。F030 可选 STOP 和恢复已接入；两端的唤醒时序尚需实机验证。

在调度器启动前初始化长期有效的 `tp_f407_uart4_subordinate`，并将其 `subordinate` 成员地址赋给业务配置的 `subordinate` 字段。默认配置不启用此端口；初始化失败后应复位重试。应答有效期从最后一个字节的中断 tick 时间开始计算，任务处理时仍检查请求超时；时间精度受 1 ms tick 和中断延迟影响。UART 时序、中断延迟、队列容量和目标板通信均未验证；请求令牌不是身份认证，复位后的会话隔离仍需系统设计。

## 阀门参考输出

`tp_f407_valves` 按旧设备树映射 19 路低电平有效阀门，初始化先预置关闭电平；设备复位期间需要外部上拉及适合的功率驱动保持关闭。初始化必须传入双向一致的流路互斥规则；全零规则仅表示不限制，不能作为实际流路安全验证。更换组合时先关闭全部电气输出再开启新组合，但不等待机械阀关闭，因此实际流路需要按阀的动作时间增加步骤间等待及硬件保护。代码尚未由主程序调用。

## 步进泵参考驱动

`tp_f407_pump` 独占 TIM4，使用 PD13 STEP、PD14 DIR 和 PD15 低有效 EN。设备复位时须由外部电路将 EN 保持在禁用状态，STEP 保持低电平。一个 TIM4 单脉冲完成后才由中断计数并启动下一个；传入的频率为标称值，实际间隔包含中断延迟，支持范围 30–1000 Hz。停止立即禁用驱动并可能截断当前脉冲。计数不检测丢步或流量；实际驱动器的脉冲宽度、方向与使能时序、精度和故障保护仍需验证。代码尚未接入主程序。

## 加热 PWM 参考驱动

`tp_f407_heater` 独占 TIM2，以 PA15 产生低有效 1 Hz PWM，0 表示关闭，1 表示全功率。须由单一控制任务管理；无效设定会立即切换到高电平关闭。复位期间须通过外部上拉保持关闭，并使用独立超温切断和适合的功率级；CPU 或调度器卡住时硬件定时器仍会输出，不能把软件 PID 当作独立保护。引脚、占空比、输出极性和功率级均需实测，代码尚未接入主程序。

## 外部反应池温度参考输入

`tp_f407_temperature` 使用 ADC1 PA0：10 kΩ 上拉至 ADC 参考电压，10 kΩ B3950 NTC 接地，低优先级任务约每 50 ms 更新一次。读取接口为非阻塞，样本无效或过期时返回错误；实际温度精度依赖探头曲线、阻值、参考源与校准。初始化会复位所有 ADC 并占用 ADC 公共分频，后续其他 ADC 用途需要统一管理。代码尚未接入主程序或验证实际探头，独立超温保护仍然必要。

## 业务装配接口

`tp_f407_app_init` 在调度器启动前连接阀门、泵、加热、ADS1220、FRAM、RTC、温度、控制服务及 USART3。调用方必须提供长期有效的配方、阀门互斥表、非阻塞互锁与资源状态回调、ADC 寄存器及通道换算参数，以及有效的默认配置。这里没有假设真实化学配方或液位安全规则。函数返回成功后才能启动调度器；失败后不要启动调度器或重复初始化，应复位后重试。I2C 存储读取失败和 ADS1220 配置读回失败均会报告错误。默认配置的来源和存储序列可从 app 对象读取；修改从站地址后需保存并复位才会用于串口端口。

默认的 `main.c` 只运行心跳。可用 `-DTP_F407_BUSINESS=ON` 构建业务入口：该入口先调用 `tp_f407_board_options`，然后调用 `tp_f407_app_init`，成功后启动调度器。默认配置函数返回错误，固件关断参考输出并停机；调试器可读取 `tp_startup_result`。用 `-DTP_F407_BOARD_CONFIG=配置文件的绝对路径` 指定实现该函数的 C 文件，提供完整的长期有效配置；未提供配置时业务入口不会运行检测。初始化失败后不启动调度器，也不在同一次启动中重试。任务栈、32 KiB FreeRTOS 堆、优先级和实时性尚需目标板验证，断言关断不能代替独立保护。

## 事件日志

装配层为 MB85RC16 的 256–2047 字节建立 56 条循环日志，配置占用的 0–255 字节与日志隔离。日志任务在调度器启动后按需扫描设备并写入；控制任务只复制事件到 16 项队列，不执行 FRAM I/O。记录包含序号、UTC 有效位、事件类型、故障或结果、CRC 和最后提交字节；完成记录中的结果采用 32 位浮点位模式。掉电或总线失败可能造成记录丢失，队列满或写入失败通过 `tp_freertos_event_log_stats` 计数；失败的提交字节可能实际已写入，后续扫描以存储内容为准。F407 装配层提供 Modbus 异步查询，具体寄存器见 `../docs/MODBUS.md`；后台查询的 RTOS 调度链路尚未运行级验证，心跳入口不运行装配层。

## 控制任务看门狗

业务装配入口最后启动 IWDG，调用方须立即启动调度器。监督任务每 100 ms 检查一次，控制任务每完成一次循环报告进度，1000 ms 无进展即关闭中断并紧急关断输出，等待独立看门狗复位。IWDG 使用 LSI、分频 256、重装值 1250；实际复位时间依赖芯片 LSI 频率，必须实测。仅监督控制任务，其他任务尚未纳入；调度、启动时序和实际保护效果未经硬件验证。看门狗不能代替独立超温保护。

## 启动前自检

装配方必须提供非阻塞 `resource_faults` 回调，返回试剂、液位故障位；无法确定状态时返回 `TP_PREFLIGHT_RESOURCE_UNKNOWN`。每次启动前检查互锁、有效温度、温度上限和资源状态；任何失败会阻止启动。运行期间的试剂和液位安全条件还必须纳入 `interlocks_ok`，该回调会在控制周期中持续检查。硬件传感器与阈值由实际装配确定。

## 参考升级串口

`tp_f407_upgrade_uart_init` 可在调度器启动前创建专用任务，使用 USART2 PA2/PA3 AF7、115200 8N1、16 MHz HSI 和不分频的 APB1。传入长期有效的 `tp_upgrade_commands`、帧超时、任务栈字数与优先级；命令、启动状态和下载存储须由该任务独占，认证与镜像校验及存储回调由装配方提供。建议先配置至少 2048 个 32 位栈字，再根据完整回调的实际栈高水位调整。默认入口不调用此初始化函数。

接收中断将字节及时间戳写入 256 项队列，任务处理帧和升级操作；UART 错误或队列溢出后丢弃当前帧。发送在专用任务内限时等待，发送失败时操作可能已完成，应由客户端查询状态。客户端必须逐帧等待响应；队列容量、任务优先级、长时间擦写和硬件流控需要按实际系统测量。该接口已交叉编译及链接，主机寄存器/RTOS 替身测试覆盖接收错误、队列溢出、帧超时和发送卡住；未在实物上验证；参考引脚、电平、时钟和升级访问控制须按实际系统确定。当前链接布局和默认入口不构成独立 Bootloader，可信认证和 Flash 适配仍待接入。
Windows 下若 ARM 链接器在响应文件中无法读取含中文的目标文件路径，可用只含 ASCII 字符的目录联接指向 `freertos` 源码，并在 ASCII 路径下重新配置构建。当前工具链通过此方式完成了 F407 交叉编译和链接；这不代表目标板已验证。


## 参考双镜像 Flash 分区

`tp_f407_image_flash` 假定 STM32F407VG 具备 1 MiB Flash：镜像槽 0 位于 `0x08020000..0x0807ffff`（扇区 5–7），槽 1 位于 `0x08080000..0x080dffff`（扇区 8–10），每槽 384 KiB。它通过调用方提供的底层读取、按扇区擦除和按字节编程接口实现镜像槽操作；活动槽来自可信启动状态，擦写请求不能修改活动槽。写入前检查完整范围和 Flash 的 1→0 位转换，逐字节编程并回读，允许中断后重试相同数据。擦除失败可能已部分完成，重试需重新擦除整个非活动槽。

`tp_f407_flash_controller` 提供参考控制器驱动：解锁、按字节编程、扇区擦除、错误检查、锁定和 Flash 缓存失效；通过 `tp_f407_flash_controller_init` 取得底层回调并传入分区层。调用时只允许一个所有者，禁止与其他 Flash 操作并发；`poll_limit` 是循环次数而非时间保证。忙等待超时后操作结果不确定，实例锁定，必须复位系统后再读取持久状态，不得通过重新初始化绕过。实际扇区擦写的供电条件、看门狗、调度时序、独立启动程序和元数据存储仍需装配。默认 `standalone` 构建仍覆盖整个 Flash，不能与升级分区同时使用；可选槽位构建限制应用位于对应槽，独立启动器参考工程见 `../firmware_boot/README.md`，板级配置仍待实现。片上 Flash 单 bank 的擦写可能阻塞取指，实时控制和安全输出必须另行设计。测试使用内存替身，未验证实物行为。
寄存器替身测试覆盖解锁失败、状态错误、读回失败与忙超时；控制器代码尚未在实机运行。字节编程要求芯片及供电处于数据手册允许的电压范围；擦除可能阻塞从 Flash 取指，所以循环次数不能提供可靠的实时超时或执行器停机保证。


## 双槽应用构建

`TP_F407_IMAGE_SLOT` 可选 `standalone`（默认，整个 1 MiB Flash）、`0` 和 `1`。槽 0 和槽 1 分别限制在 0x08020000–0x0807ffff、0x08080000–0x080dffff，每个槽必须分别编译和签名；不可把一个槽的二进制用于另一个槽。构建同时生成 ELF、HEX 和原始 `tp_f407.bin`，原始二进制用于对应槽的签名和传输。槽位编译示例：

```sh
cmake -S firmware -B build-f407-slot0 -G Ninja "-DCMAKE_TOOLCHAIN_FILE=$PWD/firmware/arm-gcc.cmake" -DTP_F407_IMAGE_SLOT=0
cmake --build build-f407-slot0
python tools/check_f407_slot.py 0 build-f407-slot0/tp_f407.elf build-f407-slot0/tp_f407.bin
```

槽 1 将上述槽号和构建目录换成 1。检查工具验证 ELF 中所有加载段的地址与长度、二进制长度、向量表地址、初始栈与复位入口；它不是签名验证。链接器拒绝超过槽容量的镜像。`SystemInit` 在 C 运行时初始化前把 VTOR 设置为当前镜像的向量表地址。当前默认入口仍是心跳程序；要构建业务入口需设置 `TP_F407_BUSINESS` 并提供板级配置。独立启动器参考工程已接入处理器交接；可信密钥、板级装配以及实机测试仍需完成。


## F407 启动交接

`tp_f407_handoff` 接受 `tp_boot_target_prepare` 成功返回的目标；目标镜像须从验证到跳转保持不可修改。函数要求特权线程模式、FAULTMASK 清除，并对槽、入口和 SRAM 栈范围再次作基本检查。成功路径关闭 SysTick，禁用并清除 82 个外部中断，清除 PendSV 和 SysTick 待处理位，设置 VTOR；最后在汇编中清除 BASEPRI、切换 MSP 和 CONTROL、开放中断并跳转。成功不会返回。

调用前必须在启动器中停止所有 DMA、外设中断源和定时器，保证没有待处理的 NMI/故障，关闭或安全设置执行器，并将时钟和外设恢复到应用所需的启动状态。IWDG 一旦启动不能在跳转时关闭，应用必须在其超时前接管。此接口本身不认证镜像，也不重置外设；不能从异常处理程序或正在运行的 RTOS 调用。主机测试只检查交接前寄存器操作，已对交叉编译产物的汇编切换序列进行检查，真实芯片行为尚未验证。

## 升级与试运行服务装配

板级配置可在 `tp_f407_app_options.start_services` 中调用 `tp_f407_upgrade_service_start`，这个回调在业务对象初始化完成后、看门狗和调度器启动前运行。服务按顺序初始化专用升级 FRAM 与签名升级组件、创建试运行确认任务、创建 USART2 升级任务；两项任务使用同一组存储锁回调。升级选项的 `app` 必须指向当前应用，`runtime` 必须指向该应用的 runtime；试运行确认同时要求应用健康和板级 `healthy` 回调通过，两个回调每次都会执行以消费各自锁存的故障。服务自动调用 `tp_f407_app_trial_healthy(app)`：控制任务每次循环检查空闲状态、维护状态和启动前检查，将两次确认采样之间的不健康观察及控制器故障锁存，并要求每次采样之间至少有一次新的控制循环；该函数还检查监控任务至少完成过一次心跳且没有超时。只有单个试运行确认任务可以消费这个状态。其检查不包括全部板级硬件自检，板级回调仍须补充并锁存额外故障；设备处于运行、故障、完成或维护状态时此检查不通过。

板级代码须读取真实 `SCB->VTOR` 提供运行槽，提供可信身份、公钥及隔离后的 FRAM 总线，并确保升级 Flash 操作期间设备已进入安全状态、禁止并发恢复运行，且看门狗策略覆盖单 Bank Flash 操作可能造成的停顿。完成回调须处理确认失败并安排安全复位；调度器启动前任一步失败不得继续启动，也不可直接重试，因为已有任务可能创建。默认板级仍未启用此服务；USART、升级总线及健康策略尚未在实物验证。

### 双 FRAM 参考总线

业务应用默认使用 I2C2（PB10/PB11）。如同时使用参考启动器和升级 FRAM，可在业务选项设置 `app_options.business_i2c = 3`，将业务 FRAM 和 DS3231 接到 I2C3（PA8/PC9），并在板级启动服务回调中以长期有效的 `tp_f407_i2c` 对象调用 `tp_f407_i2c_init`，把其 `tp_f407_i2c_io` 作为升级 FRAM 总线。这样升级 FRAM 保持连接 I2C2，与参考启动器一致，两颗同地址 FRAM 分属不同总线。两条总线均要求外部上拉、APB1 16 MHz 和独立所有权；不可再次初始化已由业务应用占用的外设。实际接线、器件地址和电气时序尚需验证。

### 精简参考入口

`tp_f407_upgrade_reference_start` 可直接接入业务入口，内部从 VTOR 读取运行槽并提供共享锁。以下是装配示意，具体硬件对象、可信公钥和参数须由板级实现提供：

```c
static tp_f407_upgrade_reference upgrade_ref; /* 零初始化，直到复位都有效 */

/* 在调用 tp_f407_app_init 前配置： */
upgrade_ref.options.storage.fram_bus = board_upgrade_fram_bus;
upgrade_ref.options.storage.flash_ops = board_flash_ops;
upgrade_ref.options.storage.product_id = board_product_id;
memcpy(upgrade_ref.options.storage.public_key, board_public_key, 64);
upgrade_ref.options.ctx = &board_context;
upgrade_ref.options.healthy = board_trial_healthy;
upgrade_ref.options.finished = board_trial_finished;
/* 同时设置 frame_timeout_ms、stable_ms、max_gap_ms、period_ms、
 * trial_timeout_ms，以及两个任务的栈大小和优先级。 */
app_options.start_services = tp_f407_upgrade_reference_start;
app_options.services_ctx = &upgrade_ref;
```

Flash 回调可通过 `tp_f407_flash_controller_init` 获得；升级 FRAM 总线须与业务 FRAM 隔离。其他升级元数据或镜像访问也必须使用 `tp_f407_upgrade_reference_try_lock` 和 `tp_f407_upgrade_reference_unlock`，并正确配对。启动后不得修改 `upgrade_ref.options`；板级健康回调须检查并锁存自身故障，完成回调须处理失败。板级仍须针对单 Bank Flash 写入制定安全输出和看门狗策略。以上示意尚未接入默认板级配置，也未上板验证。

## 自动两点标定配置

板级选项可把 `auto_calibration` 指向长期有效的 `tp_f407_auto_cal_options`；其中提供低、高标准液各自的配方数组、长度、浓度（mg/L）和最小吸光度差。应用先加载配置并初始化存储，再验证并装配两套配方；选项为空则不启用。配方及其引用数据在应用运行期间不得修改。具体阀路、泵量、反应条件、光学通道和标准液参数必须由所采用的检测方法确定。

通过 Modbus 命令 6 开始，两次启动均执行现有自检；寄存器 90、91 表示状态和错误。成功后命令 7 应用，命令 4 发起保存并通过寄存器 17 确认。控制任务负责串行操作，标定中可以随时停机。仅有板级配置接口，默认板级入口仍拒绝启动，未进行实机验证。

自动标液核查可由板级选项 `auto_standard` 指向长期有效的 `tp_f407_auto_standard_options`，提供配方、标准液浓度及绝对容差；初始化检查配方驱动限制，再接入控制服务。选项为空时功能不可用。标准液切换由提供的配方完成，需结合实际管路配置。

### 有线升级和暂存 OTA 的组合入口

`tp_f407_ota_reference` 将已有的有线升级服务与 W25Q128 暂存服务按顺序启动，可直接作为 `tp_f407_app_options.start_services`：

```c
static tp_f407_ota_reference ota; /* 生命周期覆盖整个应用 */
/* 板级代码填写 ota.upgrade.options 的存储、身份、健康及完成回调，
 * 并填写 ota.stage_options 的超时、任务栈和优先级。 */
ota.stage_ctx = board_context;
ota.stage_finished = board_stage_finished;
options->services_ctx = &ota;
options->start_services = tp_f407_ota_reference_start;
```

需要包含 `tp_f407_ota_reference.h`。有线升级使用 USART2；暂存接收使用 USART6 和 SPI1，连接网络网关后可接收 OTA 镜像。两个服务共享升级锁和维护状态，任一初始化失败均返回错误；此时必须安全停机并复位，不能启动已部分创建的任务。板级仍须提供独立升级 FRAM 总线、公钥和产品身份、结果回调，以及适用于单 Bank Flash 擦写的安全输出和看门狗策略；业务 FRAM 的参考总线应与升级 FRAM 分离。具体参数参见相关头文件和各服务说明，组合接口不会自动烧录或初始化启动元数据。该装配尚未实机验证。

### 教学装配示例

`tp_f407_teaching_config.c` 展示检测步骤、阀门互斥、ADC 通道、参数及安全回调，也配置了低、高两套标准液演示配方，供自动两点标定和标液核查调用。标准液选择、反应条件及浓度均为教学示例，不是实际仪器方法。构建时可以传入 `-DTP_F407_BOARD_CONFIG=<该文件的绝对路径>`，同时启用 `-DTP_F407_BUSINESS=ON`，检查示例是否能与业务固件一起编译。默认示例返回 `TP_INVALID`，启动入口会关断输出并停机；互锁也不通过，资源状态未知。

可显式启用 F030 参考装配，用于理解两板软件链路：在上述构建选项之外设置 `-DTP_F407_TEACHING_SUBORDINATE=ON`。此时 UART4 使用 PC10/PC11，500 ms 轮询、200 ms 超时、1500 ms 状态有效期；F030 需运行相应从控入口和参考输入。主控在从控状态未知、过期或报告故障时拒绝启动，运行期间发现故障会安全停机。该选项假定液位、试剂和漏液状态由 F030 提供，没有额外本地互锁；参考配方、通道与接线仍须按实际设备修改。默认关闭此选项。

要演示 F030 STOP 与主控唤醒，在上述主控选项外增加 `-DTP_F407_TEACHING_WAKE=ON`；F030 同时启用 `TP_F030_SUBORDINATE`、`TP_F030_REFERENCE_INPUTS`、`TP_F030_WAKE_INPUT` 和 `TP_F030_STOP_SLEEP`。参考连接为 F407 PC10 → F030 PA10、F030 PA9 → F407 PC11、F407 PC8 → F030 PA8，并共地。主控将唤醒线拉高后示例等待 10 ms 再发送；F030 STOP 需要 LSE RTC，等待时间、串口、电平与休眠行为均需实机验证。默认不启用唤醒线。

其中配方、通道、换算系数和参数仅用于解释软件结构，不是总磷化学方法或真实硬件设置。确定实物后应另建板级配置，依据原理图和方法填写各项、接入真实安全输入并验证保护，参考装配仅供教学，不能作为经过验证的实际设备配置。学习检测流程可先运行 `examples/simulator.c` 对应的主机模拟器。

### W25Q128 参考 SPI 接口

可选接口 `tp_f407_w25q128_spi` 独占 SPI1：PA4 为片选，PA5、PA6、PA7 分别为 SCK、MISO、MOSI。时钟配置要求系统及 APB2 均为 16 MHz，SPI 为模式 0、1 MHz。事务最多 260 字节，采用非阻塞互斥锁和 10 ms 总时间限制；超时包含被其他任务抢占的时间。初始化只能在调度器启动前调用一次，不可在中断中使用。与 SPI2 上的 ADS1220 分离；器件的 WP、HOLD 和片选上拉等电气连接须按实际电路确定。

接口仅编入固件，默认不初始化或启动。Flash 驱动和暂存适配器需要单一使用者管理整个擦写操作，并提供单调时钟和等待回调；事务互斥锁不代替整个操作的串行化。可选暂存任务在接收和校验完成后请求维护状态并复制到片内执行槽；默认入口尚未启用，实际网络链路、接线及运行均未实机验证。

`tp_freertos_flash_now_ms` 和 `tp_freertos_flash_sleep_ms` 可作为暂存适配器的时间回调；它们要求 1 kHz、至少 32 位的 FreeRTOS tick，只能在运行中的后台任务使用。等待两次 tick，以保证跨越至少 1 ms，不阻塞调度器。tick 计数以 32 位毫秒回绕，单次超时需小于半个计数周期。调用方仍负责把 Flash 的整次操作串行化，并确定任务栈、优先级和看门狗策略。

### 暂存镜像复制核心

`tp_staged_copy` 复用下载状态机，把经过调用方完整认证的暂存镜像逐块复制到目标槽；可从有效的元数据检查点恢复中断的擦除和写入。目标验证回调必须再次验证完整镜像及签名元数据；原始暂存、目标、签名上下文和下载元数据须由一个后台任务独占。开始及重启恢复时都会验证源；初始元数据无有效副本且非空时，拒绝自动覆盖。每次 step 最多复制 256 字节，但擦除和镜像校验本身可能耗时。调用方必须从可信启动状态保护活动槽和待启动槽，并自行装配源、目标、签名及状态存储；复制成功不会自动将镜像设为启动目标。可选 F407 暂存服务已将该流程接入维护状态和共享锁，默认入口尚未启用。

### 暂存复制与业务维护

业务升级服务启动后，可调用 `tp_f407_upgrade_staged_init(&service, &guard)`，为外部下载任务绑定维护请求与升级共享锁。任务随后调用 `tp_staged_guard_begin`；返回 `TP_LOCK_BUSY` 时等待控制任务进入维护状态或等待共享锁后重试。成功后同一任务调用 `tp_staged_guard_step` 直至成功，再调用 `tp_staged_guard_finish`；出错或中途放弃时调用 `tp_staged_guard_abort`。共享锁在整个复制会话中保持，避免与串口升级和试运行确认交错；暂存源也必须由调用方独占，不能在复制时修改。guard 初始化一次并保持地址不变，所有操作必须在同一任务串行执行。维护模式一旦进入会保持到复位。后台任务和暂存区配置仍由板级或网络模块提供，默认入口不会自动启动下载。

### 暂存升级 USART6 参考传输

`tp_f407_stage_uart` 为暂存升级任务提供一个可选的字节传输：USART6 的 PC6 TX、PC7 RX，AF8，115200 8N1，假定 HSI 16 MHz、APB2 无分频。初始化时调用 `tp_f407_stage_uart_init(&uart, &options.transport, ctx, finished)`，再调用 `tp_f407_stage_service_start`；对象、选项内的回调上下文与完成回调在整个运行期间保持有效。`finished` 在升级任务中运行，报告安装结果；成功也不代表试运行已经确认。初始化或后续装配失败应停止启动并复位，不能重复初始化。

接收中断把字节和 tick 放入 512 项队列；帧错误或队列溢出会清空队列并中止会话。发送在任务中等待，整个应答最多等待 200 ms。USART6 在暂存任务首次接收时启用，发送方须等待系统启动、逐帧等待回复并在超时后按协议查询或重试。串口不提供连接状态检测、认证或加密；本地维护口或外部网络网关必须负责访问控制及必要的安全传输。它只提供串口链路，并未实现阿里云设备端协议。引脚、电平、任务配置、队列容量及实机通信尚需验证。

`tp_f407_stage_reference_start` 将 SPI1、W25Q128、暂存存储、USART6 和暂存任务按顺序组装起来。板级 `start_services` 钩子先启动 `tp_f407_upgrade_reference`，再把其中的 `service`、长期有效且零初始化的 `tp_f407_stage_reference`、任务时间和栈配置传给该函数。它保留 W25Q128 的 0–0x5ffff 和 0x60000–0xbffff 为两个暂存分区，整块器件必须由此服务独占；其余存储、可信公钥、产品身份、试运行健康策略和升级完成后的处理仍由板级确定。任一初始化失败后应安全停机并复位，不能继续启动调度器。参考配置没有自动启用此流程。

### 教学配置中的升级装配

在 F030 教学业务配置基础上，可设置 `TP_F407_TEACHING_OTA=ON`、`TP_F407_IMAGE_SLOT=0` 或 `1`，并用 `TP_F407_TEACHING_IDENTITY_SOURCE` 指定定义产品 ID 和 64 字节 P-256 公钥的 C 源文件。身份必须与参考启动器一致，并先按 `firmware_boot/README.md` 初始化可信启动元数据；测试身份不能用于实际设备。两个槽应分别构建和签名。

此装配将业务 FRAM 和 DS3231 放在 I2C3，升级 FRAM 放在 I2C2；W25Q128 使用 SPI1，直接升级使用 USART2，暂存传输使用 USART6。接线和存储容量需按实际板卡确认。暂存安装结束或超时会关闭输出并复位，启动器决定试运行或回滚；直接串口升级成功且 USART2 应答发送完成后也会关闭输出并复位；发送超时不会复位，发送方可重试 FINISH。试运行检查业务互锁，示例没有额外板级健康输入。初始化只能在调度器启动前执行一次。

该配置仅经过构建和主机测试，尚未实机验证。实际使用前须测量 FreeRTOS 堆、各任务栈余量，并核对片内 Flash 擦写耗时与独立看门狗期限；Flash 控制器的轮询次数不代表固定时间。功能、复位和掉电恢复均需在目标板测试。

## 可选从控 IO 状态互锁

启用 `TP_F407_TEACHING_SUBORDINATE=ON` 和 `TP_F407_TEACHING_STATUS_INPUT=ON`，F407 PC12 设置为下拉输入，连接 F030 PB0（从控启用 `TP_F030_STATUS_OUTPUT=ON`）并共地。PC12 低电平阻止启动并在运行时触发互锁；高电平还须结合 UART 的有效状态才能运行。线路、电平和时序需实机验证，内部下拉不能替代适合实际电路的外部设计。
