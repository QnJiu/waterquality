# 主从状态协议核心

本协议核心处理完整帧，不包含串口收发、分帧、F030 固件或传感器驱动。整数均为小端，CRC 为 CRC-16/Modbus，校验范围不包含帧末的 CRC 两字节，CRC 低字节在前。

`tp_sub_node` 将从控串口字节流、资源状态快照与液滴计数连接起来。输入回调必须返回一致的状态快照；读取失败映射为设备故障。液滴事件须由同一个所有者处理，计数饱和或调用 `tp_sub_node_count_error` 报告事件丢失后锁存设备故障，直到重新初始化；计数为当前运行期间快照，不跨复位保存。该节点可与门锁服务并行集成，但尚不包含 PN532 传输、F030 中断或低功耗驱动。

| 请求字节偏移 | 内容 |
|---|---|
| 0 | 类型 `0x51` |
| 1 | 协议版本 `1` |
| 2–5 | 32 位请求令牌 |
| 6–7 | CRC |

| 应答字节偏移 | 内容 |
|---|---|
| 0 | 类型 `0x52` |
| 1 | 协议版本 `1` |
| 2–5 | 请求令牌 |
| 6 | 故障位：bit 0 试剂、bit 1 液位、bit 2 设备故障；其他位为零 |
| 7 | 保留，必须为零 |
| 8–11 | 32 位液滴计数快照 |
| 12–13 | 保留，必须为零 |
| 14–15 | CRC |

主控初始化超时、状态有效期及首个令牌后，调用 `tp_sub_master_request` 生成请求；传输层发送后将完整应答交给 `tp_sub_master_receive`。同一时刻只能有一个未完成请求。调用 `tp_sub_master_tick` 清理超时请求和过期状态；无效应答不会刷新状态，也不会立即取消请求。超时后上次成功状态仍可用，直到状态有效期届满，轮询周期、超时和有效期须共同配置。超时与有效期均为 1 到 `INT32_MAX` 毫秒，时钟使用 32 位毫秒计数，并须在小于 2^31 毫秒的间隔内持续调用和检查。

启动前无有效应答、状态过期或设备故障映射为资源状态未知；试剂和液位故障分别映射到对应自检故障。`healthy` 仅在状态有效且所有故障位为零时为真。调用方须在从控状态未知时显式设置设备故障，保证提供给 `tp_sub_reply` 的状态快照一致，并将该结果接入主控启动自检与运行互锁。各接口须由单一所有者串行调用，跨任务访问须自行同步。

令牌只用于匹配在途应答，32 位计数会回绕；CRC 只检测传输错误，不提供身份认证或防重放。主控复位后若重复使用令牌，旧应答可能被接受，部署时需要清空传输缓冲并设计会话机制或可靠的变化初值。液滴计数只是当前快照，尚未定义从控复位后的持久化或累计计量语义。

## 轮询服务

`tp_sub_poll` 提供周期调度，第一次调用 `tick` 即发起请求，以每次发送尝试的时间作为下一周期起点；轮询周期不得短于应答超时。发送回调必须非阻塞地复制完整帧，且不能在回调中重入该服务。发送返回非 `TP_OK` 时取消当前请求并立即将上次状态设为未知；轮询在下个周期再次尝试。应答接收和状态读取与 `tick` 必须在同一所有者任务中执行，通信任务应通过队列投递完整帧。队列丢帧、无法发送、时钟停滞及任务停滞的处理由系统集成负责。

在控制器任务中使用同一毫秒时间源，启动前通过 `tp_sub_poll_resource_faults` 提供资源自检结果，运行时将 `tp_sub_poll_healthy` 与其他安全互锁条件取与。定期调用轮询并及时处理接收帧；如果任务本身停滞，仍需独立的监督和硬件保护。主机集成测试覆盖离线阻止启动、状态过期导致泵停机、故障上报和恢复；实际串口、调度和板级安全回路尚未接入或验证。

## 字节流适配

`tp_sub_link` 为主控和从控提供串口字节流适配，双方须配置相同波特率和字符位数，并采用 `tp_rtu_receiver` 的静默间隔分帧规则。主控创建轮询链路，从控提供状态快照回调；发送回调必须复制完整帧并非阻塞。从控只对有效请求读取快照并应答。快照或发送失败会返回错误，不发送成功应答；主控状态按有效期变为未知。

UART 每个字节携带接收完成时间调用 `tp_sub_link_byte`，错误或队列溢出调用 `tp_sub_link_error`，主控遇到串口错误会立即使当前状态未知并取消未完成请求。周期调用 `tp_sub_link_tick` 前必须交付所有已收到字节并确认硬件没有未处理字节；有未完成帧时主控不会发起新轮询。回调和接口均由同一任务串行执行，微秒及毫秒参数取自同一单调时钟，计数允许回绕。CRC 错误或其他无效帧不会刷新状态；调用方应记录返回错误并继续周期调用。发送队列、串口中断、收发冲突控制、收发器方向和停滞监督仍由板级系统负责；该层不提供身份认证或复位后防重放。

存在接收队列时可使用 `tp_sub_link_byte_at` 同时传入字节接收和处理的毫秒时间，两个时间使用同一时钟，间隔必须小于 2^31 毫秒。接受有效应答时，请求超时按处理时间检查，状态有效期从该帧最后一个字节的接收时间计算；过期的应答不会重新使状态有效。原 `tp_sub_link_byte` 保留处理时间语义。

## FreeRTOS 与 F407 接入

`tp_freertos_subordinate` 使用单元素队列发布主控状态快照；UART 任务独占字节、错误和轮询接口，控制任务通过健康状态和资源故障读取函数访问快照。调度器启动前初始化一次；传入的毫秒时间必须与 1 kHz FreeRTOS tick 同源，微秒时间须与其一致并满足分帧精度。控制任务以读取时的 tick 检查最后成功应答的有效期，因此 UART 任务停滞不会让旧状态永久有效。初始化失败后的对象不能使用，重复初始化需要系统复位或由调用方释放资源。

F407 装配选项 `subordinate` 可以指向已初始化的对象。非空时，运行互锁同时要求原板级互锁和从控状态健康，启动前自检将板级资源故障与从控故障合并；空指针则沿用板级回调。初始化及 UART 任务仍由板级配置负责，默认配置没有启用该功能。主机使用队列替身覆盖快照过期和故障传播；实际 FreeRTOS 调度、UART 事件及主从硬件链路尚未运行级验证。

F407 提供可选 `tp_f407_uart4_subordinate` 参考实现，采用全双工 115200 8N1，使用 UART4 中断队列与独立任务，详见固件 README。调度器启动前初始化并将其 `subordinate` 成员交给装配选项；实际引脚、电气接口、从控协议实现及任务调度须经目标板验证。UART 错误和接收队列溢出由通信任务报告并使状态未知；任务停滞时，控制任务按最后成功应答时间判断状态过期。
