# PN532 命令驱动

`tp_pn532` 实现普通帧命令、ACK、响应匹配与校验，不支持扩展帧。传输接口与芯片无关：`send` 须复制完整请求，`receive` 返回一个完整帧或 `TP_BUSY`。两者应有有限的执行时间，且同一对象的所有操作须串行化。

一次典型 Type A 寻卡流程：芯片复位和就绪后初始化驱动，先发送 `SAMConfiguration` 命令 `0x14`，参数为 `{0x01, 0x14, 0x01}`，检查完成响应；然后发送 `InListPassiveTarget` 命令 `0x4a`，参数为 `{0x01, 0x00}`，轮询 `tp_pn532_tick`，通过 `tp_pn532_take` 取回响应数据，再交给 `tp_pn532_type_a_parse`。无目标和目标存在分别通过 `found` 区分，当前解析器接受 4、7 或 10 字节 UID，不解析可选 ATS。UID 只能作为标签标识，不能证明标签真实或授权。

调用方设定整个命令的毫秒超时；`tick` 在截止时拒绝继续接收，错误、超时或发送失败会进入 `TP_PN532_DESYNC`。此时必须先由板级代码复位芯片并清理传输缓冲，或通过经过验证的方案重新同步，之后才能调用 `tp_pn532_init`。不可仅重新初始化软件对象并假定芯片状态已恢复。调用间隔必须小于 2^31 毫秒；接收回调返回完整帧时不包含传输层状态字节。

PN532 I2C 适配需处理设备地址、就绪状态字节和单次事务读取完整帧；当前项目尚无该适配、PN532 启动控制或实机测试。设备工作模式、接线和芯片供电由最终板级设计确定。当前驱动只提供通用命令机制和 Type A 响应解析，不实现 MIFARE 数据读写、标签认证、耗材数据库或试剂有效期策略。
