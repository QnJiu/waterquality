# 升级与回滚核心

`boot.c` 管理两个镜像槽的启动决策，使用独立的双副本元数据存储，不能与参数区、事件日志或镜像槽重叠。元数据写入先擦除目标副本，再写入并回读主体，最后写提交标志并回读；发生 I/O 错误后必须重新读取状态，不得假定写入一定未生效。两个副本均损坏时拒绝启动决策；仅允许可信工厂流程在两个记录区域均为 0xff 时初始化。

升级流程：下载器只写入非活动槽，并完成完整镜像写入；`tp_boot_stage` 校验镜像后记录候选版本。下次启动再次校验候选镜像，先持久化试运行状态，再选择候选槽。应用完成健康检查后调用 `tp_boot_confirm`；如果再次复位前没有确认，启动器验证并恢复原确认镜像。候选无效时也恢复原镜像；读取或校验设备 I/O 失败则不选择镜像。所有操作需要单一所有者串行执行，下载器不得同时改写正在验证或启动的镜像。

调用方的 `verify_image` 必须验证完整镜像边界、产品兼容性、版本、签名和完整性，并区分镜像无效与设备 I/O 故障。当前仅提供接口，尚无签名算法、公钥保护、Flash 布局、固件跳转、下载传输及硬件适配；本模块不能单独构成安全 Bootloader。元数据 CRC 只检测意外损坏，版本比较不能防止攻击者回滚元数据；防恶意回滚需要可信的不可回退版本存储。设备应用应在充分自检后确认镜像，不能启动即确认。

主机测试模拟了元数据写入各步骤发生错误、提交已生效但回读失败、候选镜像损坏、校验 I/O 失败和未确认复位。闪存擦除粒度、电源故障特性及实际密钥保护仍需目标硬件验证。

`download.c` 提供顺序分块下载和断点恢复：先持久化擦除状态，再擦除目标槽；每块写入并回读后更新偏移；完整镜像通过调用方校验后才标为 VERIFIED。元数据使用独立双槽，与启动状态和镜像区域隔离。调用方必须确认目标槽既非活动镜像也非已暂存镜像，并提供可信清单；当前接口没有自动检查启动状态或自动调用 `tp_boot_stage`。

写入报错后必须重新读取偏移，若偏移没有前进，须以完全相同的偏移、长度和数据重试；底层必须支持对已部分写入的相同内容重复编程。首次元数据提交中断可能导致两槽均无有效记录且不全为空，此时拒绝继续，需由可信维护流程检查并恢复；当前没有取消下载或恢复损坏元数据的接口。实际 Flash 对重复编程和擦除的支持、签名校验与传输均尚未实现或验证。

`upgrade.c` 将下载与启动状态串联：开始、恢复和写入时要求启动状态空闲、目标槽非活动槽且版本递增；结束时完成下载校验，再由启动模块独立校验并暂存。若暂存提交成功但回读报错，重试结束操作可识别已暂存的相同槽和版本。上述检查和实际读写之间要求所有启动、下载和升级操作由同一所有者串行执行，不能绕过协调层并发调用底层修改接口；重启时还需按同一约束安排启动决策。清单认证和容量检查仍由调用方负责。

`tp_upgrade_command_execute` 为串口或网络适配层提供完整消息级命令处理：STATUS 查询下载状态；BEGIN 将清单原文交给认证回调，通过后开始；RESUME 恢复中断的擦除；WRITE 接收四字节小端偏移和最多 256 字节数据；FINISH 校验并暂存。STATUS、RESUME、FINISH 不带数据，WRITE 至少携带一个数据字节。回复包含操作结果和可选的持久化下载状态；操作结果表示命令结果，`state_available=false` 表示本次状态读取未成功，STATUS 本身返回状态读取结果。传输层负责分帧、长度限制、完整性校验、响应编码、超时和访问控制；本接口不直接收发字节流。

`tp_upgrade_wire` 提供可用于字节流的参考帧层：帧以 `7e` 开始和结束，内容中的 `7e`/`7d` 编码为 `7d` 后接原字节异或 `20`。解码内容依次为版本 `01`、命令、16 位请求序号、16 位数据长度、数据和 CRC-16/Modbus，整数均小端；CRC 覆盖版本到数据，数据最长 512 字节。响应命令为请求命令或 `80`，其数据为结果码、状态有效标志；状态有效时依次附加阶段、槽号、版本、镜像大小、已写偏移（后三项均 32 位小端）和 32 字节清单 ID。序号仅用于匹配回复，不防重放。无效长度、转义或 CRC 不执行命令，不发响应，下一帧分隔符恢复同步。

串口任务逐字节调用 `tp_upgrade_wire_byte`，串口错误或接收超时时调用 `tp_upgrade_wire_reset` 并等待新帧；发送回调在返回前复制完整帧。命令执行和发送可能阻塞，使用专门的升级任务并串行化访问；若发送失败，操作仍可能已生效，应查询状态确认。发送方应限制清单大小并按序等待应答，现场仍需实现 UART 或网络收发及丢包重试。帧 CRC 不提供认证、保密或抗重放，升级接口的访问控制、可信清单和镜像验证由系统提供。帧处理使用数百字节栈空间，实际线程栈需测量。

`../tools/upgrade_client.py` 是 Python 3 参考发送端，支持 TCP 和串口（串口需要安装 `pyserial`）。例如：

```text
python freertos/tools/upgrade_client.py --tcp 127.0.0.1:9000 --manifest manifest.bin --manifest-id <64位十六进制ID> --image firmware.bin
python freertos/tools/upgrade_client.py --serial COM3 --baud 115200 --manifest manifest.bin --manifest-id <64位十六进制ID> --image firmware.bin
```

清单及 ID 必须由具体认证方案生成，ID 须与设备认证回调生成的 32 字节值一致，镜像文件须与清单匹配。工具在超时后查询持久化状态，并只在 ID、大小与预期一致时继续；无法证明本地文件内容与清单匹配，需要镜像校验器最终验证。超时可能发生在设备已执行操作后，连接中断时重新运行并核对设备状态；首次 BEGIN 和其他错误不保证可自动恢复。TCP 为明文，实际网络需要安全传输和访问控制。设备侧 UART/TCP 驱动、真实认证方案和端到端实机测试尚未提供。

断线或写入结果不确定时先查询持久化偏移：偏移已前进表示该块已提交，否则以相同内容重传；如果查询失败，不能推测是否写入。FINISH 可以重试。认证回调必须验证签名及产品兼容性、槽容量，并生成与可信清单绑定的持久化 ID；下载和启动时的镜像校验必须独立验证完整性及真实性，不能把 CRC、传输完整性或清单 ID 当作签名。该接口的测试认证回调只是替身，实际签名验证、设备侧收发、Flash 驱动和独立启动程序仍待实现。

主机联通测试通过共享库将 Python 发送端连接到 C 帧处理、升级和启动核心，覆盖丢失应答、断线续传、拒绝清单和损坏镜像。测试使用内存存储和固定内容的认证与镜像校验替身，不验证真实签名或设备。构建时检测到 Python 解释器后，`ctest --test-dir build --output-on-failure` 会运行该测试；也可设置 `TP_UP_SIM_LIB` 为构建出的 `upgrade_simulator` 共享库绝对路径后运行 `python -m unittest discover -s tests -p test_upgrade_interop.py -v`。

`tp_upgrade_stream` 为单连接提供字节流会话：按接收时刻检查帧间超时，在空闲时轮询超时，并在串口溢出、断线或连接切换时复位。接收事件和空闲轮询必须按时间顺序交付；带时间戳的队列应先排空再按当前时间轮询。计时器使用 32 位毫秒回绕运算，超时上限为 2^31-1 毫秒。发送回调仍须完整复制或发送响应；超时与断线不能撤销已执行的升级操作。实际 UART/网络收发、任务调度、访问控制和存储仍需接入。
`tp_image_sha256` 使用 TinyCrypt v0.2.8 以 256 字节缓冲区分块计算指定镜像的 SHA-256；`tp_image_sha256_verify` 比较完整摘要。调用方提供镜像读取回调和每个槽的容量，长度为零或超出槽容量时拒绝读取，读取失败原样返回。摘要必须来自已认证的清单，且校验期间禁止并发擦写。该组件尚未连接 `tp_download_io.verify` 和 `tp_boot_io.verify_image`；仅使用哈希不能证明镜像来源，完整安全启动还需要签名认证、可信密钥和受保护的镜像布局。
