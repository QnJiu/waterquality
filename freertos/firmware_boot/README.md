# F407 独立启动器参考工程

本工程连接升级专用 FRAM 中的启动状态与签名清单、P-256 签名和镜像校验、试运行及回滚状态机、向量检查和 F407 处理器交接。默认 `unconfigured.c` 始终返回错误，启动器进入停机路径；它不能直接启动设备。失败状态可通过调试器查看 `tp_boot_startup_result`。

```powershell
cmake -S <源码目录>/firmware_boot -B <构建目录> -G Ninja `
  -DCMAKE_TOOLCHAIN_FILE=<源码目录>/firmware/arm-gcc.cmake `
  -DTP_BOOT_BOARD_CONFIG=<板级实现的绝对路径>
cmake --build <构建目录>
```

省略 `TP_BOOT_BOARD_CONFIG` 可构建停机版本。链接脚本限制启动器位于 `0x08000000` 起的 128 KiB；应用槽 0 和槽 1 分别位于 `0x08020000` 和 `0x08080000`，各 384 KiB，参见 `../firmware/README.md`。

板级实现须提供 `tp_f407_boot_board_options` 和 `tp_f407_boot_board_quiesce`。前者初始化安全输出，并提供同步轮询 I²C、只读镜像访问、产品 ID 和来自可信不可变来源的公钥；上下文须持续有效。升级专用 MB85RC16 与配置/日志用的器件占用相同 I²C 地址，须使用独立总线或隔离通道。公钥及产品身份应由可信生产流程配置和保护；`tests/boot_signed_fixture.h` 中的公开测试密钥绝不能用于部署。清单、镜像及启动状态必须先通过可信工厂流程初始化，本启动器不会自动初始化空白或损坏的状态。

### 参考访问接口

启动器构建将 `tp_f407_i2c` 编译为 `TP_F407_I2C_POLL_ONLY`，无 FreeRTOS 依赖。板级代码可先调用 `SystemCoreClockUpdate()` 和 `tp_f407_i2c_init()`，再将 `tp_f407_i2c_io()` 返回值赋给 `fram_bus`。该参考总线使用 I2C2、PB10/PB11、外部上拉、HSI/APB1 16 MHz 和 100 kHz；仅允许启动器单一执行者访问，不提供物理总线解锁。升级 FRAM 必须与业务用 FRAM 位于独立总线或隔离通道；同一时刻不能将两个同地址器件接在该参考总线上。轮询超时依赖 Cortex-M DWT 周期计数器正常运行。

`tp_f407_boot_flash_reference_init()` 设置两个固定槽的只读映射，`tp_f407_boot_flash_read` 可作为 `image_read`，对象地址作为 `image_ctx`。读取会拒绝槽外访问；板级代码必须保证对应 Flash 实际可读且在认证至跳转期间不可写。I²C 对象和 Flash 映射对象需保持有效到交接。默认构建未选择这些接口；板级初始化、可信密钥及安全清理仍由部署方提供。

板级清理须停止 DMA、定时器和外设中断源，确保安全输出，并将时钟和外设恢复到应用预期的启动状态。IWDG 如已启动，应用必须及时接管。验证到跳转期间必须禁止改写镜像及清单，所有相关持久化操作须串行。启动失败时进入停机路径；本工程不提供启动器侧升级恢复通道，也没有防恶意回滚机制。

主机集成测试使用真实 P-256 签名和内存 I²C、镜像替身，覆盖试运行、回滚、镜像篡改和 I/O 错误；参考启动器已经交叉编译。参考 I²C 和 Flash 访问已交叉编译，板级接线、可信密钥和实际装配未完成，以上结果不代表真实硬件运行或掉电验证。
