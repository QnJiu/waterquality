# F407 独立启动器参考工程

本工程连接升级专用 FRAM 中的启动状态与签名清单、P-256 签名和镜像校验、试运行及回滚状态机、向量检查和 F407 处理器交接。默认 `unconfigured.c` 始终返回错误，启动器进入停机路径；它不能直接启动设备。失败状态可通过调试器查看 `tp_boot_startup_result`。

```powershell
cmake -S <源码目录>/firmware_boot -B <构建目录> -G Ninja `
  -DCMAKE_TOOLCHAIN_FILE=<源码目录>/firmware/arm-gcc.cmake `
  -DTP_BOOT_BOARD_CONFIG=<板级实现的绝对路径>
cmake --build <构建目录>
```

省略 `TP_BOOT_BOARD_CONFIG` 可构建停机版本。链接脚本限制启动器位于 `0x08000000` 起的 128 KiB；应用槽 0 和槽 1 分别位于 `0x08020000` 和 `0x08080000`，各 384 KiB，参见 `../firmware/README.md`。

板级实现须提供 `tp_f407_boot_board_options` 和 `tp_f407_boot_board_quiesce`。前者初始化安全输出，并提供同步轮询 I²C、只读镜像访问、产品 ID 和来自可信不可变来源的公钥；上下文须持续有效。升级专用 MB85RC16 与配置/日志用的器件占用相同 I²C 地址，须使用独立总线或隔离通道。公钥及产品身份应由可信生产流程配置和保护；`tests/boot_signed_fixture.h` 中的公开测试密钥绝不能用于部署。清单、镜像及启动状态必须先通过可信工厂流程初始化，本启动器不会自动初始化空白或损坏的状态。

### 使用参考板级装配

`reference_board.c` 将上述接口组装为以硬件复位为入口的参考启动路径：关闭中断并设置参考执行器安全电平，更新时钟，初始化 I2C2 和 Flash 读取，然后配置身份。交接前等待 I²C 总线空闲、关闭 I2C2 并将 PB10/PB11 设为输入。此实现假定没有之前启动的 DMA 或其他外设；从其他程序跳转进入、不同接线、执行器极性或启动时钟等情况必须另写板级实现。参考安全引脚只能用于相同硬件接线，实际电路必须确认上电和复位期间也安全。

使用 `-DTP_BOOT_REFERENCE_BOARD=ON -DTP_BOOT_IDENTITY_SOURCE=<身份源文件绝对路径>` 构建。身份源文件须包含 `tp_f407_boot_identity.h`，定义 `const uint32_t tp_f407_boot_product_id` 和 `const uint8_t tp_f407_boot_public_key[64]`；公钥为 P-256 的大端 X、Y 坐标拼接，产品 ID 非零。启动器自身及公钥需要通过适当的芯片写保护与生产流程保护，不能把公开测试密钥当作可信部署密钥。构建时缺少身份源会报错；空公钥或零产品 ID 会使启动停机，实际签名验证还会检查公钥和签名有效性。不得同时指定自定义板级文件。首次安装仍需可信烧录镜像，并通过受控生产流程安装签名清单与启动元数据；可使用 `../bootloader/README.md` 中的工厂初始化接口。

### 工厂首次初始化固件

首次安装可单独构建工厂初始化入口，使用 `../tools/sign_manifest.py` 生成与槽位镜像匹配的 TPU1 清单，并提供与普通启动器一致的可信产品身份和公钥。例如，在参考板构建参数中增加：

```powershell
-DTP_BOOT_FACTORY_MANIFEST=<签名清单文件的绝对路径>
```

该选项生成的固件占用启动器区域，嵌入清单并只执行一次初始化，然后安全停机；`tp_factory_result` 可通过调试器读取，`TP_OK` 表示成功。镜像须事先烧录至清单所指定的槽，工厂入口会验证签名、产品、镜像向量表、镜像哈希和空白启动元数据，再写入清单及启动记录。相同内容的成功初始化可重复执行；已有不同状态或损坏元数据不会自动清除。写入返回错误时实际状态可能已改变，须重新检查；部分损坏状态需要受控恢复。

初始化成功后，需要将**普通启动器**重新烧录到启动器区域，再启动设备；烧录工具不得全片擦除，否则会破坏应用镜像。普通启动器须使用相同可信身份，最终还需保护启动器和公钥。清单与镜像应在可信环境下生成和烧录；工厂程序只验证并登记已写入的镜像，不提供镜像烧录或串口生产协议。当前流程已完成主机模拟与交叉编译，未进行实机验证。

### 参考访问接口

启动器构建将 `tp_f407_i2c` 编译为 `TP_F407_I2C_POLL_ONLY`，无 FreeRTOS 依赖。板级代码可先调用 `SystemCoreClockUpdate()` 和 `tp_f407_i2c_init()`，再将 `tp_f407_i2c_io()` 返回值赋给 `fram_bus`。该参考总线使用 I2C2、PB10/PB11、外部上拉、HSI/APB1 16 MHz 和 100 kHz；仅允许启动器单一执行者访问，不提供物理总线解锁。升级 FRAM 必须与业务用 FRAM 位于独立总线或隔离通道；同一时刻不能将两个同地址器件接在该参考总线上。轮询超时依赖 Cortex-M DWT 周期计数器正常运行。

`tp_f407_boot_flash_reference_init()` 设置两个固定槽的只读映射，`tp_f407_boot_flash_read` 可作为 `image_read`，对象地址作为 `image_ctx`。读取会拒绝槽外访问；板级代码必须保证对应 Flash 实际可读且在认证至跳转期间不可写。I²C 对象和 Flash 映射对象需保持有效到交接。默认构建未选择这些接口；参考板级装配可显式选择，部署方仍须提供可信身份并确认接线和安全清理。

板级清理须停止 DMA、定时器和外设中断源，确保安全输出，并将时钟和外设恢复到应用预期的启动状态。IWDG 如已启动，应用必须及时接管。验证到跳转期间必须禁止改写镜像及清单，所有相关持久化操作须串行。启动失败时进入停机路径；本工程不提供启动器侧升级恢复通道，也没有防恶意回滚机制。

主机集成测试使用真实 P-256 签名和内存 I²C、镜像替身，覆盖试运行、回滚、镜像篡改和 I/O 错误；参考启动器已经交叉编译。参考 I²C 和 Flash 访问已交叉编译，板级接线、可信密钥和实际装配未完成，以上结果不代表真实硬件运行或掉电验证。
