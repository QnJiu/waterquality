# STM32F407 FreeRTOS 启动骨架

这是独立的交叉编译目标，暂以 STM32F407VG（1 MiB Flash、128 KiB 主 SRAM）为参考芯片；引脚、外设、外部晶振和检测配方均未配置。时钟采用复位后的 16 MHz HSI，CMSIS 启动代码初始化 FPU，FreeRTOS 使用 Cortex-M4F 硬浮点端口。固件只创建每秒递增 `tp_scheduler_heartbeat` 的任务，调试器可观察该变量。它不启动检测业务，不操作泵、阀或加热器；断言会关中断，强制参考阀门、泵使能和加热输出进入关闭状态后停机；复位阶段、CPU 卡死以及独立硬件保护仍需另行处理。

需要 CMake、Ninja 和 arm-none-eabi-gcc（本机使用 GCC 16.1.0）。在本目录执行：

```powershell
cmake -S . -B build -G Ninja "-DCMAKE_TOOLCHAIN_FILE=$PWD/arm-gcc.cmake"
cmake --build build
```

输出 `tp_f407.elf`、`tp_f407.hex` 和 `tp_f407.map`。链接使用 nosys，未提供标准 I/O 系统调用，工具链可能对此发出警告。链接时保留板级装配入口及其依赖，检查完整链路能否链接；当前心跳主程序并不调用该入口。必须核对实物型号、Flash 大小、引脚、电气安全态和保护电路后才能实现板级对接；此链接布局尚未划分 Bootloader 或 OTA 区域。实机尚未验证。

依赖来源：FreeRTOS Kernel V10.5.1（随源码 MIT 许可）；CMSIS 5.9.0 Core（Apache-2.0）；ST CMSIS Device F4 v2.6.10 与 STM32F4 HAL/LL 头文件 v1.8.5（许可证各随目录保存）。项目目前只引入 LL 头文件，尚无具体 LL 外设驱动实现。

## 参考存储总线

`tp_f407_i2c.c` 提供 I2C2 到 `tp_i2c_io` 的适配，假设单主机、PB10=SCL、PB11=SDA（AF4）、外部上拉、APB1 16 MHz、100 kHz，目标器件为 MB85RC16。此引脚没有出现在旧设备树的阀门或 USART3 分配中，仍须按实际原理图核对。初始化前调用 `SystemCoreClockUpdate()`；驱动只接受 HSI 16 MHz 且 AHB/APB1 不分频的配置。I2C 操作限时，错误后重置外设；物理总线卡死需要硬件恢复，驱动不会自动输出九个恢复脉冲。事务在调度器启动前单线程执行，调度后使用互斥锁；只在低优先级存储任务调用。

连接顺序：`tp_f407_i2c_init` → `tp_f407_i2c_io` → `tp_mb85rc16_init`（存储区起始 256 字节对齐）→ `tp_mb85rc16_store` → `tp_runtime_bootstrap_storage`。各对象及其上下文须长期有效。当前心跳主程序不调用这条链路；I2C 时序、上拉、电气参数、总线错误恢复和掉电保存都尚未在目标板验证。

## ADS1220 SPI2 参考接口

`tp_f407_ads1220_spi` 假定系统和 APB1 均为 16 MHz，使用 SPI2 模式 1、1 MHz，PB13 SCK、PB14 MISO、PB15 MOSI、PB12 软件片选，PE14 上拉输入作为低有效 DRDY。初始化必须在调度器启动前执行一次，设备实例持续有效；接口不可从中断调用。传输竞争时立即返回忙，单次事务上限 5 字节，循环等待设有 1 ms 周期计数期限（不限制抢占时间），错误时释放片选并重置 SPI。该设备需与 SPI2 的其他使用者共享同一互斥策略。

本接口和通用 ADS1220 驱动已列入交叉编译，但尚未由心跳主程序初始化，链接垃圾回收可能移除它们；引脚电气连接、时序和模拟采样均未在硬件上验证。

## USART3 / RS485 参考端口

`tp_f407_usart3_rtu` 使用 PD8 TX、PD9 RX、PD10 高电平使能 RS485 发送，收发器 DE 与 /RE 相连；TIM5 独占用于 1 MHz 微秒计时。系统时钟和 APB1 为 16 MHz，通信参数固定为 115200 8N1。任务接收中断事件并调用 RTU 分帧器，控制任务通过发送接口复制响应；队列溢出会丢弃当前帧，发送完成中断释放方向。需要在调度器启动前绑定 runtime，主程序的发送回调再转发到此接口。端口尚未接入当前主程序，时间戳含中断延迟且排队/抢占行为未经目标板测试；确认收发器及接线后用逻辑分析仪验证时序。

## 阀门参考输出

`tp_f407_valves` 按旧设备树映射 19 路低电平有效阀门，初始化先预置关闭电平；设备复位期间需要外部上拉及适合的功率驱动保持关闭。初始化必须传入双向一致的流路互斥规则；全零规则仅表示不限制，不能作为实际流路安全验证。更换组合时先关闭全部电气输出再开启新组合，但不等待机械阀关闭，因此实际流路需要按阀的动作时间增加步骤间等待及硬件保护。代码尚未由主程序调用。

## 步进泵参考驱动

`tp_f407_pump` 独占 TIM4，使用 PD13 STEP、PD14 DIR 和 PD15 低有效 EN。设备复位时须由外部电路将 EN 保持在禁用状态，STEP 保持低电平。一个 TIM4 单脉冲完成后才由中断计数并启动下一个；传入的频率为标称值，实际间隔包含中断延迟，支持范围 30–1000 Hz。停止立即禁用驱动并可能截断当前脉冲。计数不检测丢步或流量；实际驱动器的脉冲宽度、方向与使能时序、精度和故障保护仍需验证。代码尚未接入主程序。

## 加热 PWM 参考驱动

`tp_f407_heater` 独占 TIM2，以 PA15 产生低有效 1 Hz PWM，0 表示关闭，1 表示全功率。须由单一控制任务管理；无效设定会立即切换到高电平关闭。复位期间须通过外部上拉保持关闭，并使用独立超温切断和适合的功率级；CPU 或调度器卡住时硬件定时器仍会输出，不能把软件 PID 当作独立保护。引脚、占空比、输出极性和功率级均需实测，代码尚未接入主程序。

## 外部反应池温度参考输入

`tp_f407_temperature` 使用 ADC1 PA0：10 kΩ 上拉至 ADC 参考电压，10 kΩ B3950 NTC 接地，低优先级任务约每 50 ms 更新一次。读取接口为非阻塞，样本无效或过期时返回错误；实际温度精度依赖探头曲线、阻值、参考源与校准。初始化会复位所有 ADC 并占用 ADC 公共分频，后续其他 ADC 用途需要统一管理。代码尚未接入主程序或验证实际探头，独立超温保护仍然必要。

## 业务装配接口

`tp_f407_app_init` 在调度器启动前连接阀门、泵、加热、ADS1220、FRAM、RTC、温度、控制服务及 USART3。调用方必须提供长期有效的配方、阀门互斥表、非阻塞互锁回调、ADC 寄存器及通道换算参数，以及有效的默认配置。这里没有假设真实化学配方或液位安全规则。函数返回成功后才能启动调度器；失败后不要启动调度器或重复初始化，应复位后重试。I2C 存储读取失败和 ADS1220 配置读回失败均会报告错误。默认配置的来源和存储序列可从 app 对象读取；修改从站地址后需保存并复位才会用于串口端口。

`main.c` 仍然只运行心跳，尚未提供具体业务配置或调用该接口；链接保留装配入口仅证明目标代码可链接。任务栈、32 KiB FreeRTOS 堆、优先级和实时性尚需目标板验证，断言关断不能代替独立保护。

## 事件日志

装配层为 MB85RC16 的 256–2047 字节建立 56 条循环日志，配置占用的 0–255 字节与日志隔离。日志任务在调度器启动后按需扫描设备并写入；控制任务只复制事件到 16 项队列，不执行 FRAM I/O。记录包含序号、UTC 有效位、事件类型、故障或结果、CRC 和最后提交字节；完成记录中的结果采用 32 位浮点位模式。掉电或总线失败可能造成记录丢失，队列满或写入失败通过 `tp_freertos_event_log_stats` 计数；失败的提交字节可能实际已写入，后续扫描以存储内容为准。日志尚无上位机读取接口，且心跳入口不运行装配层。
