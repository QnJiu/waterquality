# PN532 命令驱动

`tp_pn532` 实现普通帧命令、ACK、响应匹配与校验，不支持扩展帧。传输接口与芯片无关：`send` 须复制完整请求，`receive` 返回一个完整帧或 `TP_BUSY`。两者应有有限的执行时间，且同一对象的所有操作须串行化。

一次典型 Type A 寻卡流程：芯片复位和就绪后初始化驱动，先发送 `SAMConfiguration` 命令 `0x14`，参数为 `{0x01, 0x14, 0x01}`，检查完成响应；然后发送 `InListPassiveTarget` 命令 `0x4a`，参数为 `{0x01, 0x00}`，轮询 `tp_pn532_tick`，通过 `tp_pn532_take` 取回响应数据，再交给 `tp_pn532_type_a_parse`。无目标和目标存在分别通过 `found` 区分，当前解析器接受 4、7 或 10 字节 UID，不解析可选 ATS。UID 只能作为标签标识，不能证明标签真实或授权。

调用方设定整个命令的毫秒超时；`tick` 在截止时拒绝继续接收，错误、超时或发送失败会进入 `TP_PN532_DESYNC`。此时必须先由板级代码复位芯片并清理传输缓冲，或通过经过验证的方案重新同步，之后才能调用 `tp_pn532_init`。不可仅重新初始化软件对象并假定芯片状态已恢复。调用间隔必须小于 2^31 毫秒；接收回调返回完整帧时不包含传输层状态字节。

`tp_pn532_i2c` 提供异步 I2C 帧事务适配，使用 7 位地址 `0x24`；在一次读事务中先读取就绪状态，再读取帧头和剩余帧。未就绪时结束事务并稍后重试；普通帧及 ACK 交由命令驱动进一步校验，不支持扩展帧。总线后端须支持保持读事务、根据帧头继续指定长度、最后一字节 NACK 并 STOP；所有回调须非阻塞。写入启动成功后数据缓冲保持有效直至写入完成。读启动可返回 `TP_BUSY`，其他启动或续读未被接受时视为故障；STOP 和 abort 回调须请求控制器释放总线，后续启动前自行确保释放完成。

命令超时不会自动停止尚在进行的总线操作：调用方须调用 `tp_pn532_i2c_abort`，复位 PN532 并恢复总线后再重新初始化传输与命令驱动。模拟总线测试覆盖命令、ACK、响应、未就绪及故障；F030 I2C1 参考后端及可选门锁装配见固件 README。默认入口未启用门锁，已提供可选 PA6 芯片复位参考，实机时序仍待验证。设备工作模式、接线和供电由板级设计确定；当前驱动不实现 MIFARE 数据读写、标签认证、耗材数据库或试剂有效期策略。

## 周期寻卡

`tp_pn532_scan` 在复位同步后依次执行 SAM 普通模式、RFConfiguration 有限被动寻卡重试、Type A 单目标寻卡；每次扫描完成后等待设定间隔再扫描。回调每轮报告一次，参数为空表示没有发现卡，卡片指针仅在回调期间有效。应答格式错误、通信失败或命令超时会锁定故障；调用方必须检查 `tick` 的返回值或 `state`，不能把最后一次成功报告当作持续有效的门锁授权。恢复前先复位并同步芯片和通信，再重新初始化扫描器。

扫描周期和命令超时须结合芯片、总线和有限重试次数实测配置。调度器必须持续运行，所有接口由单一任务调用；回调不得阻塞或重入。持卡期间每轮都可能上报同一 UID，去重、授权策略、门锁输出和最大开锁时间由上层实现。UID 容易复制，不应单独用于有安全要求的身份认证；本模块不实现门禁认证或物理锁控制。

## 门锁状态机

`tp_door` 提供授权请求关联、开锁限时和读卡状态过期处理。初始化时先发出关锁命令；扫描回调将卡片标识传给 `tp_door_observe`，无卡时传入 `NULL` 和长度 0。新卡或标识变化会产生请求 ID，上层完成独立认证后通过 `tp_door_authorize` 返回该 ID 和结果；离卡、标识变化或读卡状态过期会使旧请求失效。周期调用 `tp_door_tick`，扫描故障时调用 `tp_door_reader_fault`。接口和回调须由单一任务串行调用，输出回调须短且非阻塞。

持续观察同一标识不会重复请求授权或延长开锁时间；开锁期间收到的新授权会被消费，但不会延长本次开锁。离卡后按开锁限时或读卡状态过期关锁。观察过期后再次发现同一标识会发起新的授权请求。请求 ID 是会回绕的 32 位计数，重新初始化也可能重用：认证层须绑定当前运行会话并在复位后清理旧请求。标识变化只能关联软件请求，不能证明卡片真实性，也不能识别具有相同 UID 的换卡。

输出回调成功只表示命令被接受，不证明物理门锁已动作；关锁命令失败时实际状态未知，需要门锁反馈或独立保护。软件限时依赖任务和调度器持续运行，调度器停顿时需独立硬件保护。可选参考配置提供 PA5 门锁 GPIO 和本地 UID 白名单；真实认证服务及实机测试仍待完成。

`tp_door_service` 将扫描结果连接到门锁状态机，并在新请求出现时调用应用提供的认证请求回调。回调必须在返回前复制标识、非阻塞且不可重入；认证完成后由同一所有者调用 `tp_door_service_authorize`。应周期调用 `tp_door_service_tick`，认证请求提交失败或扫描错误会使门锁进入故障状态并尝试关锁。所有接口必须串行执行并使用同一单调时钟；扫描间隔、命令超时与读卡有效期应结合实际最坏执行时间配置。F030 可选装配连接 I2C 后端，认证服务和 GPIO 由板级提供，整个链路尚未实机验证。
