# Modbus RTU 寄存器（软件接口初版）

地址均为零起始 PDU 地址，寄存器为 16 位，FC03 读取，FC06/FC16 写入。多寄存器数值高字在前；浓度为 IEEE 754 32 位浮点。此协议是新工程独立定义，尚未和旧工程寄存器表兼容；F407 装配层提供 USART3/RS485 参考接入，当前心跳主程序尚未启用装配层；寄存器访问须通过控制任务串行处理。

温度快照使用控制器最近一次周期采样，标称周期 200 ms，实际更新时间取决于控制任务调度；该值不是独立的硬件安全保护。

图形上位机可用“读取模式”读取地址 1–5 的当前快照；输入框初始值只是示例。修改模式配置时必须用 FC16 一次写入地址 1–5，运行中拒绝变更。启动、停止和清故障命令必须单独写入地址 0。受控模式的启动命令执行配方第一步，之后每次以命令 5 执行一步（包括最后的结束步骤）；只有地址 18 为 1 时接受下一步命令。等待期间仍检查互锁并持续调温，30 秒内未继续则报超时故障并安全停机；停机命令随时有效。周期和每日定时模式自动执行完整配方。20–43 是 IEEE 754 32 位浮点，高字在前；20–46 必须用单次 FC16 完整写入并整体校验，运行或保存中拒绝修改。写入仅更新内存，命令 4 将配置提交到后台保存队列；命令成功只代表请求入队，须查询地址 17 确认保存结果，保存中拒绝启动。板级初始化可调用 `tp_runtime_bootstrap_storage` 加载配置并附加存储；F407 装配层已接入 STM32 I2C2 参考适配；心跳主程序尚未调用装配层。

地址 44–45 与地址 2–3 的周期同步；修改周期后从当前时间重新计时，需通过命令 4 保存。重复写入完全相同的模式参数保留原有计时和当天触发记录；改变模式参数会重新初始化调度。附加配置后周期必须在 1–2147483 秒范围内。运行模式、每日时间和 UTC 偏移随命令 4 保存，上电后恢复；旧版配置恢复为受控模式、每日 00:00、UTC 偏移 0。保存周期或每日模式后重启可能自动启动，仍需通过启动自检及安全互锁。周期从配置加载时重新计时；每日模式要求 RTC 有效，且当天已触发标记不持久化：若重启恰好处于设定分钟，可能再次触发。写入保存的从站地址不会更新运行中的串口上下文；通信地址修改后需保存并复位。

寄存器服务必须与状态机在同一任务执行。通信任务应通过请求队列交给控制任务处理，停止请求使用独立优先队列；不要直接从不同串口任务并发调用这些函数。读取多个寄存器时必须保持快照一致。实际停止响应还依赖任务调度、驱动和硬件，尚未测量。


每路串口应各持有一个 `tp_rtu_port`，初始化后对象地址保持不变。UART 中断/DMA 层须将字节完成时间戳和错误按序交给对应串口任务，任务先处理已接收字节再调用轮询；分帧后由 `tp_runtime_rtu_port_init` 绑定的提交回调将帧复制到控制队列，协议地址与 CRC 在控制任务处理。串口接收溢出应作为接收错误注入；中断中不能直接调用该适配器。发送缓存、RS485 方向和实际串口配置仍由板级实现。

进入升级维护状态后，寄存器读取、停止命令以及日志查询仍可使用；其他写入（包括清故障、参数修改、保存和校时）返回忙，直到设备复位。进入维护前已排队的后台保存或日志操作仍可能完成，维护状态不表示所有后台 I/O 已停止。

## 异步日志查询

一次 FC16 写入 50–52：模式 0 查询最新记录，后两字必须为 0；模式 1 按后两字组成的 32 位序号查询。写入成功仅表示请求已入队；轮询 53，状态为 3 时一次读取 53–64 获取一致快照。状态 4 表示日志为空或序号不存在/已被覆盖，状态 5 表示存储读取失败。请求等待期间拒绝新查询；队列满时写入失败，应稍后重试。新的查询会清除旧快照。查询和写入共用后台日志队列，低优先级任务繁忙时查询可能延迟。

图形教学上位机 `tools/tp_gui.py` 的“读取事件”支持留空查询最新记录或按序号查询，显示类型、详情、UTC 秒数和原始值，并解码带有效结果的完成事件浓度；查询为空或读取失败时会显示错误，不会沿用旧记录。事件类型和原始值含义见下文。

启动前自检由 F407 装配层执行，手动与定时启动均使用相同检查；任一故障会拒绝启动并保持输出安全，清除旧结果的有效标记；寄存器 13 报 I/O 错误，19 给出原因。温度采样尚未就绪时也会拒绝启动，可待采样有效后重试。ADC 通信错误或超时后其配置失效，清除控制器故障不会恢复 ADC；此时自检报告 128 并拒绝启动。停止运行后可发送命令 8，控制任务先关闭输出，再向 ADC 发送 POWERDOWN、重写并回读驱动保存的配置；失败会返回错误，可排查后重试。命令 8 不清除控制器故障：若控制器处于故障状态，还需执行命令 3。已配置自检时，命令 3 先关闭输出并重新自检；自检失败则保留原故障，并更新寄存器 19。未配置自检时仍检查互锁。恢复成功只表示配置回读一致，并不验证传感器接线或实时转换；寄存器 19 记录最近一次自检，可通过命令 10 或启动请求更新。运行或维护期间拒绝恢复。试剂与液位来源由装配方提供，运行期间仍须由互锁回调持续检查安全条件。

参数保存、自动标定或标液核查期间，周期和每日触发也会跳过，不会排队补跑，也不会覆盖最近一次启动结果。

上位机读取寄存器 131 显示升级维护状态；旧固件返回地址异常时显示未知。维护模式由控制任务内部锁存，进入时执行安全输出；维护期间启动和单步推进返回忙，定时触发被跳过。清除故障不会解除维护，需重启并重新初始化服务。F407 组合升级服务会在修改升级状态前申请维护，等待控制任务确认；状态查询不会触发维护。板级必须实际装配该服务并确保 Flash 擦写期间的安全输出和看门狗策略。

## 教学用串口命令行

`tools/tp_modbus.py` 通过 pyserial 访问设备，默认 115200、8N1、从站地址 1，与 F407 参考串口一致。先安装 `python -m pip install pyserial`，在 `freertos` 目录下运行：

```text
python tools/tp_modbus.py --port COM3 status
python tools/tp_modbus.py --port COM3 get-config --output config.json
python tools/tp_modbus.py --port COM3 set-config config.json
python tools/tp_modbus.py --port COM3 schedule daily 3600 480 480
python tools/tp_modbus.py --port COM3 command save
python tools/tp_modbus.py --port COM3 command start
python tools/tp_modbus.py --port COM3 command stop
python tools/tp_modbus.py --port COM3 command adc-recover
python tools/tp_modbus.py --port COM3 command self-check
python tools/tp_modbus.py --port COM3 command auto-cal-start
python tools/tp_modbus.py --port COM3 auto-cal-status
python tools/tp_modbus.py --port COM3 command auto-cal-apply
python tools/tp_modbus.py --port COM3 log-stats
python tools/tp_modbus.py --port COM3 log
python tools/tp_modbus.py --port COM3 log --sequence 1
```

`--baud`、`--address`、`--timeout` 可按设备配置调整。`schedule` 写入 RAM，需执行 `command save` 并读取状态确认保存成功；启动和保存的响应表示请求已接受，实际结果应查看状态。日志返回原始 `value_bits`；完成事件可将其按 IEEE 754 float 解码。工具按单个请求同步运行，不自动重试写命令。需要实际设备、已配置的板级入口及适配 RS485 的串口。

图形上位机的“读取参数”可查看和整组修改地址 20–46；命令行 `get-config` 导出地址 20–46 的完整 JSON，编辑后用 `set-config` 一次写入整组标定、PID、温度上限、周期和从站地址。设备负责校验参数范围，写入后仍需保存。此文件是读取时的快照，写入会覆盖整组参数；多人或多个上位机操作时先协调，避免覆盖之后的修改。运行模式、每日时间和 UTC 偏移使用 `schedule` 单独配置。更改从站地址保存并重启后，使用新的 `--address` 连接。

两点标定使用设备当前浊度系数、最小信号和浓度上限。写入 70–87 后立即计算并应用新的斜率与截距；参数不合格、设备运行中或正在保存时拒绝写入。应用后可读取 20–23 确认，命令 4 才会持久化。例如 `python tools/tp_modbus.py --port COM3 calibrate 1 1 0 0 1 0.1 0 5 0.01` 是计算示例，数字并非实际标准液或设备校准值。此命令使用外部提供的标准点；也可以使用下述自动采样标定流程。

## 可选 FreeModbus 协议栈

F407 固件可配置 `-DTP_USE_FREEMODBUS=ON`，默认关闭。各 UART 的现有 RTU 接收器负责帧间时序和错误处理，完整帧进入控制任务后由上游 FreeModbus 同步处理；所有运行实例必须由同一个控制任务串行调用，适配器不提供线程互斥。停机优先队列仍由控制任务使用。上游 FC16 一次最多写 120 个寄存器，原协议实现最多 123 个；当前应用最大写块为 27 个。该选项已通过主机模拟和交叉编译，板级配置与实机联调仍待完成。

## 自动两点标定

应用初始化时调用 `tp_service_attach_auto_calibration`，提供两套保持有效的配方、标准液浓度和最小吸光度间隔；需先附加配置存储及有效控制器配置。配方负责切换标准液和采样，必须包含三个光学读数及结束步骤，不能包含浓度计算。命令 6 启动，控制任务独占执行两套配方并在每套开始前运行已配置的自检。运行期间普通启动和保存被拒绝，停止命令会取消标定并安全停机。读取 90–91 查看进度及错误，失败时还应检查 11、19。

成功后命令 7 把拟合结果应用到内存配置；命令 4 再异步保存，读取 17 确认保存结果。配置变更会丢弃尚未应用的拟合结果。F407 教学配置包含标准液切换和采样的示例配方；正式使用需按实际方法配置配方并验证数值和检测性能。

标液核查使用当前标定参数，由上位机提供已采集的三个读数、标液浓度和 mg/L 绝对容差。完整写入 92–101 后同步计算，结果从 102–104 读取；无效输入会清除上次结果，设备运行或维护中拒绝计算。配置更新也清除结果，结果不跨复位保存。多客户端应串行执行写入和读取，因为结果是设备共享的最新结果。命令行示例：`python tools/tp_modbus.py --port COM3 check-standard 1 0.1 0 1 0.01`；示例数值仅用于演示。该接口不控制采样或切换标准液，不自动修改标定参数。

自动标液核查使用板级提供的标准液配方和浓度、容差，命令 9 启动，命令 2 可停止；配方及参数未配置时命令被拒绝。它与检测、自动标定、保存和维护互斥，启动时执行自检；配置变更会使完成的核查结果失效。通过 `command auto-standard-start` 启动，用 `auto-standard-status` 查询。手动输入的标液核查结果与自动核查结果分别保存在 102–104 和 105–109。

自动标定、标液核查及自检结果变化产生独立事件（类型 6、7、8）；重复的相同自检结果不重复记录，同时保留原有控制器启动、完成与故障事件。日志使用非阻塞队列，队列满或存储失败时记录可能丢失；这些事件不替代实时状态查询。

命令 10 可在空闲、完成或故障状态下单独执行已配置的启动前自检，并更新寄存器 19；失败会返回 Modbus 异常，同时保留故障位供读取。它不会清除控制器故障或启动检测。运行、标定、核查或维护期间拒绝；未配置自检时也拒绝。检查内容及其物理有效性取决于板级回调。

日志统计使用一次寄存器读取内的原子快照，计数器为本次上电后的 32 位数值，溢出回绕；丢弃数大于零表示可能缺失记录。查询请求不计入事件入队数，I/O 错误数与丢弃数的含义不同。

`log-stats` 以 JSON 输出日志是否可用和入队、写入、丢弃、I/O 错误计数；未接入日志时 `available` 为 `false`，计数为 `null`。

自动标定或自动标液核查尚未结束时，控制服务也会按自动流程状态拒绝参数写入、手动标定和标液核查、运行模式修改、保存、ADC 恢复及其他自动流程启动；即使底层控制器已经结束当前配方，仍要等自动流程完成或取消。

流程发生故障或被停止时，控制器会撤销本次计算结果的有效标记；清故障不会恢复旧结果。再次启动并成功完成包含计算步骤的流程后，地址 16 才报告有效。

固件版本来自升级服务启动时读取的启动元数据，并在试运行确认成功后更新。读取 119–121 应使用一次 FC03；有效标记为 0 时不能把候选版本当成正在运行的已确认版本。此接口需要装配升级服务，仍需实际板卡验证。

RTC 校时通过 FC16 向地址 123 一次写入两个寄存器，例如 Unix 秒数 1700000000 写入 `0x6553, 0xF100`。读取地址 122 等待状态 3，状态 4 表示写入或回读失败；请求接受只表示已进入后台队列。运行、标定或维护期间拒绝校时；校时期间暂停启动，旧的 RTC 时间不会用于每日定时判断。周期触发仍按忙碌时跳过处理。回读成功确认时间寄存器一致，但不保证晶振精度。校时可能改变下一次每日触发时间；已触发的日期不会因时钟回拨再次触发，重启后去重状态不保留。

使用教学上位机设置时间和查看结果（请将秒数替换成实际 UTC 时间）：

```powershell
python tools/tp_modbus.py --port COM3 set-clock 1700000000
python tools/tp_modbus.py --port COM3 clock-status
```

`clock-status` 一次读取地址 122–127，输出最后校时状态及最新时钟快照；地址 123–124 读出为零，校时期间快照无效。

升级服务试运行完成时会尝试写入事件类型 9：detail 为 `tp_result`（0 表示确认成功），value 为试运行版本号。该事件不带 UTC 时间。记录通过后台日志队列异步写入；队列满、存储出错或完成回调立即复位时记录可能丢失，可通过寄存器 110–118 查看队列丢弃及 I/O 错误计数。普通已确认版本启动不产生此事件。

命令 11 是人工触发的简易故障恢复：控制器处于故障状态且已配置 ADC 恢复和自检时，依次关闭输出、恢复 ADC、执行自检并检查清故障条件。任一步失败都保留故障；成功回到空闲，不自动重新启动或恢复原测量。维护模式及自动标定/核查进行中拒绝执行。上位机可用 `command recover`，或在图形界面点击“故障恢复”；先排除物理故障并读取状态确认结果。
