# Modbus RTU 寄存器（软件接口初版）

地址均为零起始 PDU 地址，寄存器为 16 位，FC03 读取，FC06/FC16 写入。多寄存器数值高字在前；浓度为 IEEE 754 32 位浮点。此协议是新工程独立定义，尚未和旧工程寄存器表兼容；F407 装配层提供 USART3/RS485 参考接入，当前心跳主程序尚未启用装配层；寄存器访问须通过控制任务串行处理。

| 地址 | 意义 |
|---|---|
| 0 | 命令：1 启动、2 停止、3 清故障、4 请求保存配置、5 执行下一步、6 启动自动两点标定、7 应用标定结果、8 恢复 ADC 配置、9 启动自动标液核查、10 执行自检；读取为 0 |
| 1 | 模式：0 受控、1 周期、2 每日定时 |
| 2–3 | 周期秒数，无符号 32 位；周期模式须大于 0 且不超过 2147483 秒 |
| 4 | 每日触发时间，从本地 00:00 开始的分钟数，0–1439 |
| 5 | 固定 UTC 偏移分钟，有符号 16 位，−720 至 +840 |
| 10 | 运行状态：0 空闲、1 运行、2 完成、3 失败 |
| 11 | 故障码，枚举见 `tp_core.h` |
| 12 | 当前配方步骤索引，从 0 开始 |
| 13 | 最近一次启动请求结果，枚举见 `tp_core.h` |
| 14–15 | 最近浓度结果 mg/L |
| 16 | 结果有效标记：完成且完成浓度计算时为 1，其余为 0 |
| 17 | 保存状态：0 不可用、1 已附加配置或待保存、2 保存中、3 成功、4 失败 |
| 18 | 逐步受控等待下一步：1 等待、0 未等待 |
| 19 | 最近一次自检故障位：1 互锁、2 温度传感器、4 超温、8 试剂、16 液位、32 资源状态未知、64 漏液、128 ADC 软件未就绪；32768 尚未执行 |
| 20–21 | 标定斜率 slope |
| 22–23 | 标定截距 intercept |
| 24–25 | 浊度系数 turbidity_factor |
| 26–27 | 最小信号 min_signal |
| 28–29 | 最大浓度 max_concentration |
| 30–31 | PID 比例系数 kp |
| 32–33 | PID 积分系数 ki |
| 34–35 | PID 微分系数 kd |
| 36–37 | 温控死区 deadband_c |
| 38–39 | 输出上限 output_max |
| 40–41 | 积分上限 integral_max |
| 42–43 | 温度上限 max_temperature_c |
| 44–45 | 保存的周期秒数，32 位无符号整数 |
| 46 | 保存的 Modbus 从站地址，1–247 |
| 50–52 | 日志查询请求：模式、序号高字、序号低字；必须一次 FC16 写入 |
| 53 | 日志状态：0 不可用、1 空闲、2 查询中、3 找到、4 不存在、5 I/O 错误 |
| 54–55 | 记录序号，32 位无符号 |
| 56 | 事件类型：1 启动、2 完成、3 故障、4 清故障、5 上电、6 自动标定状态变化、7 自动标液核查状态变化 |
| 57 | 事件详情，取值由事件类型决定；6、7 的低字节为对应状态寄存器值，7 完成且合格时 bit 8 为 1 |
| 58 | UTC 时间有效标记：1 有效、0 无效 |
| 59–62 | UTC 秒数，64 位有符号整数的位模式，高字在前 |
| 63–64 | 事件值，32 位位模式；普通完成事件为 IEEE 754 float 结果；7 完成时为核查浓度 float，6、7 失败时为错误码 |
| 90 | 自动标定状态：0 未配置、1 空闲、2 低点运行、3 高点运行、4 完成待应用、5 失败、6 已取消 |
| 91 | 自动标定错误码，枚举见 `tp_core.h`；故障详情另见寄存器 11 和 19 |
| 92–101 | 标液核查输入，仅支持一次 FC16 完整写入：blank、reacted、turbidity、标液浓度、绝对容差；每项为高字在前的 IEEE 754 float |
| 102 | 最近标液核查状态：0 无结果、1 合格、2 不合格 |
| 103–104 | 最近标液计算浓度 mg/L，状态为 1 或 2 时有效 |
| 105 | 自动标液核查状态：0 未配置、1 空闲、2 运行、3 完成、4 失败、5 已取消 |
| 106 | 自动标液核查错误码；控制器故障及启动自检详情另见 11 和 19 |
| 107 | 自动标液核查结果：0 无结果、1 合格、2 不合格；仅状态 3 时有效 |
| 108–109 | 自动标液计算浓度，float，仅状态 3 时有效 |
| 70–87 | 两点标定输入，仅支持一次 FC16 完整写入：低点 blank、reacted、turbidity、浓度，高点同四项，最小吸光度间隔；每项均为高字在前的 IEEE 754 float |

修改模式配置时必须用 FC16 一次写入地址 1–5，运行中拒绝变更。启动、停止和清故障命令必须单独写入地址 0。受控模式的启动命令执行配方第一步，之后每次以命令 5 执行一步（包括最后的结束步骤）；只有地址 18 为 1 时接受下一步命令。等待期间仍检查互锁并持续调温，30 秒内未继续则报超时故障并安全停机；停机命令随时有效。周期和每日定时模式自动执行完整配方。20–43 是 IEEE 754 32 位浮点，高字在前；20–46 必须用单次 FC16 完整写入并整体校验，运行或保存中拒绝修改。写入仅更新内存，命令 4 将配置提交到后台保存队列；命令成功只代表请求入队，须查询地址 17 确认保存结果，保存中拒绝启动。板级初始化可调用 `tp_runtime_bootstrap_storage` 加载配置并附加存储；F407 装配层已接入 STM32 I2C2 参考适配；心跳主程序尚未调用装配层。

地址 44–45 与地址 2–3 的周期同步；修改周期后从当前时间重新计时，需通过命令 4 保存。附加配置后周期必须在 1–2147483 秒范围内。运行模式、每日时间和 UTC 偏移随命令 4 保存，上电后恢复；旧版配置恢复为受控模式、每日 00:00、UTC 偏移 0。保存周期或每日模式后重启可能自动启动，仍需通过启动自检及安全互锁。周期从配置加载时重新计时；每日模式要求 RTC 有效，且当天已触发标记不持久化：若重启恰好处于设定分钟，可能再次触发。写入保存的从站地址不会更新运行中的串口上下文；通信地址修改后需保存并复位。

寄存器服务必须与状态机在同一任务执行。通信任务应通过请求队列交给控制任务处理，停止请求使用独立优先队列；不要直接从不同串口任务并发调用这些函数。读取多个寄存器时必须保持快照一致。实际停止响应还依赖任务调度、驱动和硬件，尚未测量。


每路串口应各持有一个 `tp_rtu_port`，初始化后对象地址保持不变。UART 中断/DMA 层须将字节完成时间戳和错误按序交给对应串口任务，任务先处理已接收字节再调用轮询；分帧后由 `tp_runtime_rtu_port_init` 绑定的提交回调将帧复制到控制队列，协议地址与 CRC 在控制任务处理。串口接收溢出应作为接收错误注入；中断中不能直接调用该适配器。发送缓存、RS485 方向和实际串口配置仍由板级实现。

## 异步日志查询

一次 FC16 写入 50–52：模式 0 查询最新记录，后两字必须为 0；模式 1 按后两字组成的 32 位序号查询。写入成功仅表示请求已入队；轮询 53，状态为 3 时一次读取 53–64 获取一致快照。状态 4 表示日志为空或序号不存在/已被覆盖，状态 5 表示存储读取失败。请求等待期间拒绝新查询；队列满时写入失败，应稍后重试。新的查询会清除旧快照。查询和写入共用后台日志队列，低优先级任务繁忙时查询可能延迟。

启动前自检由 F407 装配层执行，手动与定时启动均使用相同检查；任一故障会拒绝启动并保持输出安全，寄存器 13 报 I/O 错误，19 给出原因。温度采样尚未就绪时也会拒绝启动，可待采样有效后重试。ADC 通信错误或超时后其配置失效，清除控制器故障不会恢复 ADC；此时自检报告 128 并拒绝启动。停止运行后可发送命令 8，控制任务先关闭输出，再向 ADC 发送 POWERDOWN、重写并回读驱动保存的配置；失败会返回错误，可排查后重试。命令 8 不清除控制器故障：若控制器处于故障状态，还需执行命令 3。恢复成功只表示配置回读一致，并不验证传感器接线或实时转换；寄存器 19 记录最近一次自检，可通过命令 10 或启动请求更新。运行或维护期间拒绝恢复。试剂与液位来源由装配方提供，运行期间仍须由互锁回调持续检查安全条件。

维护模式由控制任务内部锁存，进入时执行安全输出；维护期间启动和单步推进返回忙，定时触发被跳过。清除故障不会解除维护，需重启并重新初始化服务。F407 组合升级服务会在修改升级状态前申请维护，等待控制任务确认；状态查询不会触发维护。板级必须实际装配该服务并确保 Flash 擦写期间的安全输出和看门狗策略。

## 教学用串口命令行

`tools/tp_modbus.py` 通过 pyserial 访问设备，默认 115200、8N1、从站地址 1，与 F407 参考串口一致。先安装 `python -m pip install pyserial`，在 `freertos` 目录下运行：

```text
python tools/tp_modbus.py --port COM3 status
python tools/tp_modbus.py --port COM3 get-config --output config.json
python tools/tp_modbus.py --port COM3 set-config config.json
python tools/tp_modbus.py --port COM3 schedule daily 3600 480 480
python tools/tp_modbus.py --port COM3 command save
python tools/tp_modbus.py --port COM3 command start
python tools/tp_modbus.py --port COM3 command stop
python tools/tp_modbus.py --port COM3 command adc-recover
python tools/tp_modbus.py --port COM3 command self-check
python tools/tp_modbus.py --port COM3 command auto-cal-start
python tools/tp_modbus.py --port COM3 auto-cal-status
python tools/tp_modbus.py --port COM3 command auto-cal-apply
python tools/tp_modbus.py --port COM3 log
python tools/tp_modbus.py --port COM3 log --sequence 1
```

`--baud`、`--address`、`--timeout` 可按设备配置调整。`schedule` 写入 RAM，需执行 `command save` 并读取状态确认保存成功；启动和保存的响应表示请求已接受，实际结果应查看状态。日志返回原始 `value_bits`；完成事件可将其按 IEEE 754 float 解码。工具按单个请求同步运行，不自动重试写命令。需要实际设备、已配置的板级入口及适配 RS485 的串口。

`get-config` 导出地址 20–46 的完整 JSON，编辑后用 `set-config` 一次写入整组标定、PID、温度上限、周期和从站地址。设备负责校验参数范围，写入后仍需保存。此文件是读取时的快照，写入会覆盖整组参数；多人或多个上位机操作时先协调，避免覆盖之后的修改。运行模式、每日时间和 UTC 偏移使用 `schedule` 单独配置。更改从站地址保存并重启后，使用新的 `--address` 连接。

两点标定使用设备当前浊度系数、最小信号和浓度上限。写入 70–87 后立即计算并应用新的斜率与截距；参数不合格、设备运行中或正在保存时拒绝写入。应用后可读取 20–23 确认，命令 4 才会持久化。例如 `python tools/tp_modbus.py --port COM3 calibrate 1 1 0 0 1 0.1 0 5 0.01` 是计算示例，数字并非实际标准液或设备校准值。此命令使用外部提供的标准点；也可以使用下述自动采样标定流程。

## 可选 FreeModbus 协议栈

F407 固件可配置 `-DTP_USE_FREEMODBUS=ON`，默认关闭。各 UART 的现有 RTU 接收器负责帧间时序和错误处理，完整帧进入控制任务后由上游 FreeModbus 同步处理；所有运行实例必须由同一个控制任务串行调用，适配器不提供线程互斥。停机优先队列仍由控制任务使用。上游 FC16 一次最多写 120 个寄存器，原协议实现最多 123 个；当前应用最大写块为 27 个。该选项已通过主机模拟和交叉编译，板级配置与实机联调仍待完成。

## 自动两点标定

应用初始化时调用 `tp_service_attach_auto_calibration`，提供两套保持有效的配方、标准液浓度和最小吸光度间隔；需先附加配置存储及有效控制器配置。配方负责切换标准液和采样，必须包含三个光学读数及结束步骤，不能包含浓度计算。命令 6 启动，控制任务独占执行两套配方并在每套开始前运行已配置的自检。运行期间普通启动和保存被拒绝，停止命令会取消标定并安全停机。读取 90–91 查看进度及错误，失败时还应检查 11、19。

成功后命令 7 把拟合结果应用到内存配置；命令 4 再异步保存，读取 17 确认保存结果。配置变更会丢弃尚未应用的拟合结果。自动标定尚需实际配方和标准液切换的板级配置；数值及检测性能须按具体方法验证。

标液核查使用当前标定参数，由上位机提供已采集的三个读数、标液浓度和 mg/L 绝对容差。完整写入 92–101 后同步计算，结果从 102–104 读取；无效输入会清除上次结果，设备运行或维护中拒绝计算。配置更新也清除结果，结果不跨复位保存。多客户端应串行执行写入和读取，因为结果是设备共享的最新结果。命令行示例：`python tools/tp_modbus.py --port COM3 check-standard 1 0.1 0 1 0.01`；示例数值仅用于演示。该接口不控制采样或切换标准液，不自动修改标定参数。

自动标液核查使用板级提供的标准液配方和浓度、容差，命令 9 启动，命令 2 可停止；配方及参数未配置时命令被拒绝。它与检测、自动标定、保存和维护互斥，启动时执行自检；配置变更会使完成的核查结果失效。通过 `command auto-standard-start` 启动，用 `auto-standard-status` 查询。手动输入的标液核查结果与自动核查结果分别保存在 102–104 和 105–109。

自动标定与标液核查状态变化产生独立事件（类型 6、7），同时保留原有控制器启动、完成与故障事件。日志使用非阻塞队列，队列满或存储失败时记录可能丢失；这些事件不替代实时状态查询。

命令 10 可在空闲、完成或故障状态下单独执行已配置的启动前自检，并更新寄存器 19；失败会返回 Modbus 异常，同时保留故障位供读取。它不会清除控制器故障或启动检测。运行、标定、核查或维护期间拒绝；未配置自检时也拒绝。检查内容及其物理有效性取决于板级回调。
