# STM32F030 参考启动骨架

本目标假定 STM32F030C8（64 KiB Flash、8 KiB SRAM），使用复位后的 8 MHz HSI 和 FreeRTOS Cortex-M0 端口。仅创建心跳任务，调试器可观察 `tp_f030_heartbeat`；未初始化任何业务外设或门锁；浅睡眠默认关闭。芯片型号、引脚、电源和连接须结合实物确认，尚未实机验证。

依赖现有 FreeRTOS Kernel V10.5.1、CMSIS Core 5.9.0；STM32F0 CMSIS 设备文件来自 ST 的 cmsis-device-f0 v2.3.6，提交 `8b86197c7ab77ad029c34dc73cf6d4a1e12327d8`，许可随文件保存。参考链接脚本未划分升级空间；3 KiB FreeRTOS 堆和至少 1 KiB 主栈是启动阶段的预算，实际业务接入后须重新测量栈及 RAM。

在此目录执行：

```powershell
cmake -S . -B build -G Ninja "-DCMAKE_TOOLCHAIN_FILE=$PWD/../firmware/arm-gcc.cmake"
cmake --build build
```

生成 ELF、HEX 和 map。硬件复位期间及异常状态下的锁输出安全态必须由电路与后续板级实现保证。

## 从控串口参考入口

配置 `-DTP_F030_SUBORDINATE=ON` 可构建主从状态应答入口。假定 USART1 使用 PA9 TX、PA10 RX、AF1，全双工 115200 8N1、TTL 电平；使用 TIM3 产生 1 MHz 微秒时基。8 MHz 时钟下 BRR 为 69，标称实际波特率约 115942。引脚、电平、波特率误差和时序需按硬件验证。该入口占用 USART1、TIM3 和相应中断，不执行 STOP。

USART 中断将字节和错误交给 32 项队列，单一任务处理协议；队列溢出或 UART 错误使当前帧失效。新帧到达时才发现上一帧结束的情况下，上一帧的应答会丢弃，由主控超时重试；发送中不接受另一发送。TIM3 中断若被屏蔽达 65.536 ms 或更久可能丢失计时溢出，影响分帧，实际系统必须约束中断延迟并测量。队列、任务栈、3 KiB 堆和 1 KiB 主栈保留量需要结合最终业务测量。

默认 `tp_f030_board_inputs` 返回错误，因此协议应答报告设备故障，不会把未配置的输入当作正常。可通过 `-DTP_F030_INPUT_CONFIG=源文件绝对路径` 提供 `tp_f030_board_inputs.h` 中的回调；回调须非阻塞并返回一致快照。另一种选择是在启用从控入口时配置 `-DTP_F030_REFERENCE_INPUTS=ON`，使用下述参考输入，两种配置互斥。门锁服务尚未在默认入口装配；适配器可接受已初始化的门锁服务，该服务及应用状态须由从控任务管理。异常停机不会操作尚未配置的锁输出，实机需要独立的安全态设计。

参考输入在从控任务启动后配置：PA0 为液位、PA1 为试剂状态，内部上拉，低电平正常、高电平故障；状态从一次 GPIO 读取形成一致快照，两种边沿均通知任务。PB2 内部上拉，下降沿作为液滴事件进入 ISR 暂存接口。PA3 内部上拉，高电平为漏液故障，上升沿中断锁存故障；启动时引脚已为高也会锁存。漏液通过轮询应答上报。排查并处理漏液后，维护任务可调用 `tp_f030_reference_inputs_acknowledge_leak`；只有引脚为低且无未处理的漏液中断时才清除锁存，否则返回 `TP_BUSY`。这只是从控输入确认，主控仍需收到正常状态并按自身流程清除故障；参考入口没有提供远程确认命令。此电平定义依赖实际传感器电路，例如短接到地不能被识别为故障。输入未实现去抖或滤波，EXTI 的单个待处理位无法统计中断处理前的多次边沿，不能保证高速液滴不丢失；需要结合信号速度设计硬件滤波或计数方案。引脚、电平、上拉、启动时序和事件可靠性均未实机验证，参考入口未实现 STOP。

调度器启动后，认证任务可通过 `tp_f030_subordinate_authorize` 提交请求编号与授权结果。此接口只能从任务上下文调用；`TP_OK` 表示结果进入单槽邮箱，不代表门锁接受或执行了授权，`TP_BUSY` 表示邮箱未取走，调用方需要按业务超时重试。协议任务使用处理时的时钟检查请求编号和读卡有效期；过期或不匹配的结果会被拒绝。认证服务和真实锁输出仍须由板级系统提供，UID 不能作为认证凭据。

已装配门锁服务时，可在调度器启动前用 `tp_f030_subordinate_on_door_fault` 注册故障处理回调。门锁服务首次返回错误时，由从控任务调用一次，回调须有界、非阻塞且不得重入服务；例如可在其中中止 PN532 传输。故障不会自动恢复。中止事务、恢复总线并复位同步芯片后，单一所有者可调用 `tp_f030_pn532_door_recover`；它重新初始化传输和门禁服务、保持锁关闭并保留下一个授权编号。可在调度器启动前通过 `tp_f030_subordinate_set_door_recovery` 注册有界、非阻塞的板级恢复回调，在其他任务中用 `tp_f030_subordinate_recover_door` 排队；`TP_OK` 只表示排队成功。回调由从控任务执行：等待时返回 `TP_BUSY`，完成物理复位和总线同步后调用 `tp_f030_pn532_door_recover` 并返回结果。恢复和首次读卡验证期间拒绝授权、保持设备故障；成功后重新启用故障上报，失败可再次排队。板级须实现超时和复位，不能从其他任务直接并发调用门禁服务。参考入口可通过门禁配置注册板级恢复回调，不自动发起恢复。

调度器启动后，液滴中断处理函数可调用 `tp_f030_subordinate_droplet_from_isr` 暂存事件，调用方负责将传出的唤醒标志交给 `portYIELD_FROM_ISR`。协议任务批量取走事件并更新计数；暂存或累计计数溢出均锁存设备故障。刚发生的事件要等到任务下次处理后才进入快照，计数不跨复位保存。可选参考 EXTI 已调用此接口，实际信号及丢边检测仍需板级设计和验证。

主机替身测试覆盖请求应答、背靠背帧、队列溢出、UART 错误和计时器回绕；寄存器行为、实际调度和通信均尚未实机验证。

## PN532 的 I2C1 参考后端

`tp_f030_i2c` 为 `tp_pn532_i2c` 提供非阻塞的轮询后端，独占 I2C1，参考连接为 PB6 SCL、PB7 SDA、AF1、开漏及外部上拉。时钟源为 8 MHz HSI，`TIMINGR=0x10420f13` 是标准模式参考值；总线电容、上拉、电压、频率和芯片模式必须在目标板上核验。后端在 255 字节边界重装读写计数，可在读取状态和帧头后继续同一事务，最后自动 STOP。每次轮询最多处理一个字节，命令超时必须包含任务调度和完整读写时间。

先初始化 I2C 后端，将 `tp_f030_i2c_bus` 的返回值交给 `tp_pn532_i2c_init`，再将 `tp_pn532_i2c_io` 交给 PN532 或门锁服务。访问、芯片复位和恢复须由同一所有者串行执行；错误或命令超时后先中止传输，恢复总线并复位同步 PN532，再重新初始化。软件禁用控制器不能保证释放被外设持续拉低的总线，具体恢复电路及策略需按硬件实现。默认主入口没有创建门锁服务，也没有配置 PN532 复位引脚；寄存器替身测试不能验证电气时序与芯片兼容性。

可通过 `-DTP_F030_SUBORDINATE=ON -DTP_F030_DOOR_CONFIG=板级源文件绝对路径` 启用参考装配。板级文件实现 `tp_f030_door_board_prepare`：在调度器启动前设置锁的安全态、复位并同步 PN532，提供锁输出和异步认证请求回调及时间参数；失败时入口停机。入口初始化 I2C1、帧事务和门锁服务，将门锁故障映射为设备故障，并在服务故障时中止总线操作。认证回调必须复制卡标识并非阻塞；认证任务使用 `tp_f030_door_authorize` 将结果送回单槽邮箱，邮箱满时按业务超时重试。请求编号应绑定当前运行会话，不能单独以 UID 鉴权。所有回调上下文须在固件生命周期内有效。

故障后服务锁定，不自动复位或重试。可选的 `recover_hardware` 回调由板级提供，并在 `recovery_ctx` 中保存长期有效的状态：从控任务反复调用该非阻塞回调，板级须完成必要的硬件恢复，处理中返回 `TP_BUSY`，完成返回 `TP_OK`，并自行限制总时长。参考入口随后重新初始化 I2C1 与门禁服务；维护任务使用 `tp_f030_door_request_recovery` 排队，返回 `TP_OK` 只表示已排队，最终结果由设备故障状态反映。回调失败后须允许下一次请求重新开始恢复。未配置回调时恢复请求返回 `TP_INVALID`。参考入口异常停机不保证锁输出动作；复位、断电、软件停滞和物理锁状态需要独立硬件保护。`tests/f030_door_build_fixture.c` 仅用于交叉链接测试，输出和认证均返回错误，不能用于实际硬件。所需栈、堆、I2C 时序及读卡行为尚未实测。

参考输入还使用 PA4 作为本地漏液确认按钮，内部上拉、按下接地。上电后须先释放至少 100 ms，再连续按下至少 2 秒才尝试确认；按钮在启动时一直按下不会触发。漏液仍在或漏液中断待处理时确认失败，必须释放并重新长按；清除后若再次漏液，持续按住不会自动清除。确认仅清除从控锁存，主控仍需收到正常状态并清除自身故障。按钮电路及实际响应尚未实测。

### 本地卡号白名单（教学用途）

可用 `tp_door_allowlist_init` 配置只读卡号表（支持 4、7、10 字节 UID），把 `tp_door_allowlist_request` 作为门禁配置的 request 回调。提交回调须复制并排队授权结果，例如包装 `tp_f030_door_authorize`；门禁所有者稍后处理，不能在读卡回调中重入门禁服务。空白名单拒绝所有卡，未知卡不会触发开锁。表和策略对象必须在整个门禁服务运行期间有效，且不得并发修改。排队失败视为读卡服务故障并关闭输出。

此策略只比对 UID，不验证卡片密码或身份；UID 可被复制，只适合教学或低安全性场景。真实门禁需要另行确定认证方案、授权配置及物理锁的安全状态。


## 门锁 GPIO 参考输出

`tp_f030_reference_lock_init()` 初始化 PA5：先将输出锁存器写低，再切换为推挽输出；低电平为锁定，高电平请求解锁。门禁板级配置可在初始化成功后把 `tp_f030_reference_lock_io()` 赋给 `tp_f030_door_config.lock`。门禁状态机负责限时重新锁定、读取器故障时关锁；从控入口的断言和内存/栈失败处理也会调用 `tp_f030_reference_lock_emergency_off()`。该引脚与现有 PA0–PA4 输入、USART1、I2C1 参考引脚不重叠。

这是一个输出命令，不验证锁的机械位置或电源；必须由外部驱动和上/下拉确保复位、掉电以及异常期间达到设计的安全态，并确认低电平锁定适合所用门锁。默认入口不会初始化这个输出；其他故障处理路径（例如 HardFault）也需由最终板级设计处理。引脚、电平和时序尚未实机验证。


## PN532 故障复位参考输出

`tp_f030_reference_pn532_reset` 可在从控门禁故障后复位读卡器。PA6 连接 PN532 的 `RSTPD_N`，低电平复位；PB6/PB7 为参考 I²C1。板级门禁配置中保留一个零初始化的 `tp_f030_pn532_reset`，在启动调度器前调用 `tp_f030_reference_pn532_reset_init`，并把对象指针和 `tp_f030_reference_pn532_reset_step` 分别填入 `recovery_ctx` 和 `recover_hardware`。故障后现有从控任务先中止 I²C 事务；维护端排队恢复后，回调跨多个任务周期保持复位低电平 20 tick、释放后等待 100 tick，再检查两条 I²C 线均为空闲高电平。成功后入口重新初始化 I²C 和门禁状态，读卡器首次完整交互成功才解除故障。该复位接口只用于故障恢复；上电前的设备复位及同步仍由板级启动流程负责。

要求 1 kHz、至少 32 位 FreeRTOS tick，PA6 与 PN532 电平兼容，复位线在处理器初始化前通过外部上拉保持释放，I²C 使用外部上拉；参数是参考值，需按芯片和模块手册及实测调整。总线仍被拉低时返回错误，供维护重试；该实现不产生 I²C 时钟脉冲，也不能检测复位线断开或证明读卡器已经工作。默认入口不启用，尚未实机验证。

## 可选 CPU 浅睡眠

构建时设置 `-DTP_F030_IDLE_SLEEP=ON`，空闲任务执行 WFI，且明确清除 SLEEPDEEP。CPU 等待中断时进入浅睡眠；SysTick、TIM3、USART1 及已启用的外设时钟继续运行，现有串口协议和计时不需要更改。默认关闭，心跳和从控入口均可选择启用。

这是普通睡眠，不是 STOP，也没有关闭周期性 1 ms 系统节拍；从控任务在通信和门禁空闲时最多等待 10 ms，并按门禁的下一期限缩短等待；有待处理事件、通信或门禁活动时仍按 1 ms 运行。串口及输入事件通知可提前唤醒任务。参考维护按键通过任务采样，空闲时采样间隔最多约 10 ms。周期性 SysTick 仍会唤醒 CPU，因此节电幅度有限。空闲任务检查后、执行 WFI 前若中断已处理并使任务就绪，下一次中断才会唤醒 CPU，正常 SysTick 可使这段额外延迟小于约一个节拍，实际时序仍受中断屏蔽等因素影响。电流、串口时序和系统响应尚未在硬件上验证。

## 主控唤醒输入

在从控构建中设置 `-DTP_F030_WAKE_INPUT=ON`，使用 PA8 作为高电平有效的主控唤醒输入，内部下拉，上升沿经 EXTI8 通知从控任务。该选项独占 PA8、EXTI8 和 EXTI4_15 中断入口；其他 4–15 号 EXTI 用户需要统一分发中断。将主控的唤醒 GPIO 与 PA8 正确连接并共地，确保主控在从控启动和恢复期间保持高电平。

`tp_f030_wake_input_active()` 在未初始化、引脚为高或上升沿待处理时返回真，供将来进入 STOP 前检查；睡眠入口还须在屏蔽中断时重新检查所有唤醒条件，再原子进入低功耗。本选项当前只配置输入和通知任务，没有实现 STOP 或睡眠时间恢复；接线、引脚电平与时序尚未实机验证。

## STOP 实现的计时约束

当前目标是 STM32F030C8。根据 [RM0360 Rev 5](https://www.st.com/resource/en/reference_manual/dm00091010-stm32f0x1-stm32f0x2-stm32f0x8-advanced-armbased-32bit-mcus-stmicroelectronics.pdf) 第 6.3.4、21.4.1 和 21.4.8 节，该型号 STOP 时高速时钟停止，退出后系统时钟切回 HSI；RTC 可用 LSE 或 LSI 继续运行。手册的通用 RTC 描述包含周期唤醒定时器，但 F030x8 的 RTC 框图和本工程芯片头文件没有该定时器，不能直接套用其他 STM32 的 WUT 实现。应使用 RTC Alarm A（EXTI 17）及其亚秒比较作为候选定时唤醒方案。

例如 LSE 为 32768 Hz、异步预分频为 31、同步预分频为 1023 时，亚秒计数为 1024 Hz，单次间隔约 0.977 ms；换算到 1 kHz FreeRTOS tick 需要保留小数误差，并处理计数回绕。写入闹钟前后还须防止目标时间已过，避免等待到下一次匹配。使用 LSI 时频率误差需另行处理。

退出 STOP 后，RTC 影子寄存器不会立即更新：默认影子模式须按手册清除并等待 RSF；若选择 BYPSHAD 直接读取，须按手册重复读取以确认一致。将来实现还须与 FreeRTOS tickless idle 原子配合，检查任务和外设待处理事件、计算可睡时限、补偿休眠期间的 tick 和 TIM3 时间，并处理唤醒过程中收到的主从请求。以上仅是设计约束，当前未启用 RTC 闹钟或 STOP。

`tp_f030_rtc_time` 提供上述 1024 Hz 时基的闹钟目标、跨秒计数和 1 kHz 整数 tick 换算，余数可在多次换算间保留。时间戳必须由调用方一致地采集秒和亚秒；两次采样必须间隔小于 60 秒，并设置允许的最大计数，超过该前提不能仅凭秒字段识别整分钟回绕。闹钟目标必须在目标计数到来前写入并确认，调用方还须处理 SysTick 相位和 RTC 采样误差。该代码已通过主机测试，尚未连接硬件或休眠流程。

`tp_f030_rtc` 提供直接寄存器读取及 Alarm A 装载：读取时重复比对亚秒和秒，写闹钟后检查目标是否仍有至少一个完整的亚秒周期，并拒绝已有待处理闹钟。该接口要求板级先配置 LSE、RTC 日历、31/1023 分频、BYPSHAD、备份域写入和 EXTI17/NVIC；调用方须独占 Alarm A，并在屏蔽中断时装载及检查其他唤醒源。接口不会清除已有的闹钟和 EXTI 标志，调用方负责处理中断及清理。寄存器替身测试覆盖配置检查、闹钟待处理和等待超时；闹钟同步、时序及硬件唤醒仍未实测，也尚未接入 tickless 或 STOP。
